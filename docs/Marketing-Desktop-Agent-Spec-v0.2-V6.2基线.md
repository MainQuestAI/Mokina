# Marketing Desktop Agent Spec v0.2 · V6.2 原界面原型修订

修订日期：2026-09-14。当前交付：V6.2 交互迭代原型 0.2.1，不是正式产品发布。0.2.0 Review 的四项问题以 [0.2.1 修复验收](./Marketing-Desktop-0.2.1-修复验收.md) 为准；旧记录不作为修复证据。

本文件按用户最后批准的《沿用 V6.2 的 Marketing Desktop 交互原型开发方案》修订。上一稿“先打通真实 Codex 最小闭环”的实施要求已移至后续集成；原稿完整保存在 [历史稿](./reference/Marketing-Desktop-Spec-v0.2-真实集成历史稿.md)。上一轮独立 Marketing Desktop 首页、导航与工作页不作为本轮实现或验收依据。

## 1. 本轮目标和边界

在熟悉的 V6.2 界面中，完成“提出目标 → 提供资料 → 讨论与计划 → 查看成果 → 修订与比较 → 选择性接续”。品牌战略、社媒内容、运营分析共用同一工作机制；产品上市为显式选择的专业场景。

保留原布局、配色、字体、侧栏项目树/个人会话、对话输入、协作模式、右侧面板、成果 Canvas、标签切换、比较与采用。新增字段与内容使用原组件，不能另建第二套工作台，不能通过“返回 V6.2”跳去另一产品。另存 HTML 只用于发布迭代产物；原 V6.2 HTML/ZIP 保留对照。

| 真实本地执行 | 明确标注的情景演示 | 后续真实集成 |
|---|---|---|
| 文本读取、CSV 解析计算、编辑、保存、版本、引用、导出、备份恢复 | 品牌判断、文案、计划建议、生成进度、专业场景内容 | Codex Runtime、模型质量、重连、后端、权限服务、外部连接器、发布、桌面安装包 |

不宣称模型已读、工具已调用、图片已真实生成、正式发布成功或 CL 入库成功。未支持输入不能静默回退到上市模板。自有资料替换示例后，新依据必须真实变化；旧示例成果仍保留原引用。未接模型时可以人工编辑或选择完整示例，不得换挂来源冒充生成。

## 2. V6.2 原位置的交互

| 位置 | 必须行为 |
|---|---|
| 对话式首页 | 四个场景快捷入口只选场景并填入可编辑目标；不自动发送、生成或载入资料 |
| 项目与会话 | 新工作默认无项目；一般项目名称必填，其余可选；产品上市才有专业字段 |
| 持续对话 | 一句话不自动新建工作；解释只回答；另做方案建独立成果；局部修改指向具体基础版本/条目 |
| 计划面板 | 编辑目标、交付名称/类型、输入、输出、排除项；可增删排序多个同类交付；保存不制作 |
| 工作状态/本次依据 | 选择、排除资料，指定成果版本，查看正文；开始时固定快照，调整只影响下一次 |
| Canvas | 原卡片打开、并排讨论、独立阅读、标签、返回、比较与采用；普通文档、排期、分析在此展示 |
| 成果与资料 | 当前工作/项目全部工作/全部范围有明确标识；可见不等于自动引用 |
| 独立能力 | 创建时固定所属工作及来源；离开页面、切会话再保存不能存到新导航工作 |

### 三种模式

协作：解释直接回答；明确单项制作可开始；多项先展示建议范围。

先定计划：先讨论和保存计划，用户明确开始前不制作。解释不因模式而生成成果。另做方案可以加入计划，仍需开始。

自主完成：用户确认范围后连续制作，不自动采用、批准或发布；必要输入缺失时停止并指明缺项。

用户可忽略建议或停止讨论，不强加结束流程和后续待办。

### 0.2.1：有限调整与明确开始

- 动作与否定使用同一同义表；第二个方案、另一份方案、对照方案统一识别。否定只确认，不新增成果、版本或计划项。分句允许“不要图片，只制作五条文字”；双重否定和多个含糊动作要求选择。
- 另做方案与普通制作共用校验、固定依据、可取消操作及保存入口。一次操作只生成一组条目 ID。
- 先定计划模式允许明确“开始制作／开始执行”：单项执行；多项要求选当前项或全部；全部只执行未完成项。完成后不隐式重做，另做一份需确认。自主完成不自动采用或发布。
- 面板修改目标、参数或当前交付后，通过对话开始须选择“保存并开始／使用已保存计划”，保留未保存底稿。
- 品牌固定 90 天，选 1–2 个触点：小红书、微信公众号、文字交流（依受众为答疑或家庭小组）。触点名称、用途与说明一起变化。
- 社媒 1–5 条，统一小红书或微信公众号；起始日期按日顺延，未指定保留相对排期。参数进入真实条目与下载；渠道设置不代表平台专门改写。
- 目标、输入、预期输出、排除项共同校验。支持的文字可映射 config；文字与显式参数冲突需选择。超出渠道、周期、事实或策略覆盖时允许保存计划，标记需确认演示范围，制作前阻止；人工文档由用户主动创建。
- 分析只计算所选 CSV 和明确前后期。接续必须至少保留一项支持实用内容方向的选定结论；排除全部或仅选局限不生成固定三条内容。

## 3. 最小数据契约

- 工作沿用 `thread.id`，不新增竞争性的 Work 生命周期；`projectId` 可空。
- 计划归属工作，交付项具有稳定 ID；保存变更留计划历史，不重建已有项身份。
- 交付项可选 `config` 保存触点、条数、渠道、日期；旧项从已知场景默认补齐，旧文字与默认冲突则等待确认。
- 成果按 ID 定位，类型不能作为唯一定位键。版本保存来源和固定依据快照。
- 修订绑定成果 ID、基础版本、段落/条目 ID；已有更新稿时形成冲突候选，不覆盖。
- 当前查看版本、候选版本、采用版本分开；查看和导出不隐式取最新版。
- 制作记录创建时固定工作、项目、操作者、计划版本、输入与排除项。取消后迟到/重复回调不创建成果。
- 刷新保留已有成果、资料、选择、输入框及编辑草稿；运行中模拟显示“待重新执行”。
- 旧备份显式导入，保留对象 ID、版本、引用、决定、提交快照；重复导入不复制。无法唯一判定会话归属的旧成果保留历史/共享。
- 当前存储键从首次读写前设置为 `mokina-marketing-desktop-prototype`；不自动读取旧 V6.2 存储。
- 部分引用按成果 ID、版本、段落 ID 一次解析正文、摘要和结构化片段。切版本预览和查看来源同步；旧快照不重写。缺段落、缺版本或来源撤回阻止新引用。能确认摘录与版本内容不一致的历史记录标注“历史引用不一致”，再次引用必须重新解析。

## 4. 三条主流程

### 4.1 品牌战略

北岚生活两份合成访谈：年轻租住人群、有孩子家庭。无项目讨论受众取舍、90 天沟通方向、两个触点与验证建议；不要求 SKU、FABE/MH、图片或上市项目。

验收动作：先讨论不制作 → 保存调整计划（成果数不变）→ 开始可取消演示 → 对话卡片打开 Canvas → “为什么不同时覆盖两类受众”（只解释）→ “保留方向，再补一个对照方案”（新独立成果）→ 选定方向段落修改（候选）→ 原生比较与主动采用（保留旧版/决定）。

输入变体：年轻租住者不能持续参与、有孩子家庭已有稳定交流小组；示例结果相应改为家庭方向。原结果不变。

### 4.2 社媒内容

已有事实、确认表达、旧文案直接输入，不重做上游。一个结构化成果含五条文字，每条具有稳定 ID、日期、渠道、目标、角度、正文、CTA。

Canvas 可编辑全部字段；第三条缩短生成候选，其他四条和未要求字段不变。多份同类成果时必须先定位，不按最新猜测。指定版本文字/CSV 下载内容与页面一致。不要图片或发布不成为前置要求。

输入变体：仅提供搬家文字清单，暂不提供答疑；对应示例不得保留答疑或上门服务承诺。

### 4.3 运营分析与选择性接续

原始 CSV（只读，文件见 `docs/fixtures/operations.csv`）：

```csv
period,content_type,impressions,interactions
previous,practical_tips,30000,1800
previous,product_intro,10000,300
current,practical_tips,10000,650
current,product_intro,30000,900
```

真实计算：总体 5.25% → 3.875%，下降 1.375 个百分点；实用内容 6% → 6.5%，产品介绍 3% → 3%；实用内容曝光占比 75% → 25%。

按前期分组率×本期权重得到 3.75%，结构项 −1.50 个百分点，分组率变化项 +0.125 个百分点；不是因果证明。不能据总体下降声称两类都变差。

分析面展示汇总、分组、原始输入的固定引用、计算口径、发现、两项演示实验建议与局限。可更换 CSV，显式指定前后期再计算；不按字符串排序猜时间。缺列、非数值、格式错误、零分母提示具体位置或受影响指标，不补示例数据。

接续：选分析版本和具体结论 → 预览必要摘要/引用 → 确认另开三条内容计划工作。只携带选中结论与固定版本，不复制原始 CSV、整个项目或所有结论，不声称实验有效。

## 5. 专业场景、文件与兼容

产品上市通过首页显式载入或创建产品项目；仍在同一 UI 内使用原产品输入、事实核验、单渠道计划、德国七类交付、图片成员选择、候选决定与固定提交。专业规则不拦普通营销工作。内部评审通过不等于正式批准或外部 CL 成功。

未知成果类型保留保存、卡片、详情、引用、导出、恢复；未知文件格式不伪造预览，保留文件信息和原文件下载。文本/CSV 正文真实读入；PDF、Word、图片不在本轮真实解析范围。

## 7. 构建、验证和交付

构建直接组合 V6.2 源码与 `src/marketing-desktop/{model,scenes,contracts,workspace}.js`、局部样式；不读取已启动 HTML 再覆盖原页面。原独立重做代码不参与构建。

交付包含可修改源码、`Marketing Desktop Demo.html`、完整离线包、三套合成资料、演示脚本、测试/启动命令、截图和验收记录。包必须包含所有构建资源和测试文件，并经解压后构建测试。

必须检查1440×900及1280×800；与原 V6.2 对照首页、计划、对话/Canvas、版本比较。真实浏览器选择文件、下载后检查内容，不以 toast 或 Node 状态测试抵扣。
