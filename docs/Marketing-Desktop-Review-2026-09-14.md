> 0.2.1 修复追踪：R1–R4 的原始反例已在本轮实际页面关闭，证据和补测边界见 [修复验收](./Marketing-Desktop-0.2.1-修复验收.md)。以下保留 0.2.0 当时的发现、定位和结论；旧行号不代表修复后定位。用户产品评审尚未替代或自动完成。

日期：2026-09-14。本轮只审查，不修产品代码、不重建交付包。浏览器使用三个隔离测试会话，未操作用户正在使用的浏览器数据。

审查对象：包版本 0.2.0 对应的 `Marketing Desktop Demo.html` 与当前源码；页面 SHA256：`96167b7f9e7ddfaa3480460ea14d24702ba4ad8f1c89ea912d0e8ffed706d0e9`。要求依据为当前 Spec 及用户批准的“沿用 V6.2”方案。

## 结论

暂不建议认定交互验收通过。V6.2 界面路径、基础制作和局部版本保存可用，但本轮实际页面复现了 3 项 P1、1 项 P2：排除要求未执行、否定指令反向执行、引用版本与正文错配，以及计划模式无法通过明确的对话指令开始。

这不是要求接真实模型。对于超出演示覆盖的编辑或表达，原型应明确拒绝或请求选择；不能继续生成与已确认范围冲突的示例。

## R1 · P1：计划排除项被保存，却不约束制作

定位：[scenes.js:63](../src/marketing-desktop/scenes.js#L63)，`MD.produce`。

复现：品牌战略 → 显式载入两份示例 → 发送默认目标 → 把计划“本轮排除”改成“不要小红书，不要文字答疑，只做微信公众号。” → 开始当前项。

实际：计划及固定快照保留该排除原文；成果“只维护两个触点”仍为“小红书”和“每周文字答疑”，没有冲突提示。见[页面证据](../output/playwright/review-exclusion-ignored.png)。

原因：品牌和社媒产出只依据资料变体选择固定正文，之后最多覆盖标题；计划目标、输入、预期输出及排除项没有参与范围校验。

影响：用户以为调整后的计划已生效，实际仍执行原示例。违背“计划可调整”“否定和排除必须保留”“未覆盖请求不静默生成模板”。

建议：在开始制作前核对场景支持的范围与已保存计划。支持的调整进入对应结果；不支持的范围明确停下，提供人工编辑或重新选定范围。补测排除触点、改变条数、改变交付输出，不只断言快照保存了文字。

## R2 · P1：明确不做第二方案，反而新增第二方案

定位：[workspace.js:99](../src/marketing-desktop/workspace.js#L99) 与紧接的第二方案分支。

复现：协作模式，打开一份已有品牌成果，发送“先不做第二个方案，保留当前这一份就好。”

实际：成果数量从 1 变为 2；助手回复“已新增独立对照方案，原方案保留”。新成果与用户这句话在同一次操作中保存。见[页面证据](../output/playwright/review-negation-creates-result.png)。

原因：否定分支只覆盖部分动词及“对照方案”，后续执行分支却额外接受“第二个方案／另一份方案”等表达。否定与动作采用不一致的匹配规则。

影响：常见换句话说就会产生用户明确不要的成果。在计划模式同样可能新增用户没有要求的计划项。

建议：先统一识别动作及其否定状态，再执行；不确定时只澄清。新增方案也应经过公共可取消操作入口。补测“先不做第二个方案”“不要另一份方案”“暂不制作对照方案”，确认成果数和计划项数均不变。

## R3 · P1：切换接续来源版本后，新快照混入旧结论

定位：[model.js:43](../src/marketing-desktop/model.js#L43)，以及 [workspace.js:152](../src/marketing-desktop/workspace.js#L152) 的引用版本切换。

复现：

1. 品牌成果 v1 的“优先受众与取舍”为年轻租住人群；人工编辑得到 v2，改成“Review v2：只面向有孩子家庭，暂不面向年轻租住人群。”
2. 切回 v1，只选择该受众结论，预览并确认另开工作。
3. 新工作“本次依据”将这个引用从 v1 切到 v2，完成选择。
4. 建立普通文档，打开它的来源与固定快照。

实际：新来源标记 v2，但显示的固定正文仍是 v1 的年轻租住结论。读取同一快照可见 `selected[0].revision = 2`、`text` 为 v1 正文，而 `data.sections[0].body` 已是 v2 的家庭结论。见[页面证据](../output/playwright/review-version-source-mismatch.png)。

原因：带有段落选择的引用，`MD.resolve` 从新版本取 `data.sections`，却直接沿用创建接续时缓存的 `ref.summary` 作为 `text`；切版本只修改 revision，没有重新核对摘要。

影响：新成果的版本引用与可读证据互相矛盾，可能把旧结论冒挂到新版本。影响 Spec AC-13、AC-24 的固定版本和选择性接续契约。

建议：每次解析选定引用，都从“指定版本＋稳定段落 ID”生成一致的正文和摘要；新版本不存在对应段落时要求重新选择。旧成果快照保持不变。补测“选定部分结论→切引用版本→再次制作”，不能只测整份成果的 revision 数字改变。

## R4 · P2：先定计划模式忽略明确的开始指令

定位：[workspace.js:110](../src/marketing-desktop/workspace.js#L110)。

复现：社媒场景载入三份资料，建立并保存计划，切到“先定计划”，发送“开始制作”。

实际：成果数为 0，操作数为 0；回复仍为“先把目标和交付范围放进计划”，并重新打开计划面板。之后点击面板“开始当前项”则正常生成五条内容。见[页面证据](../output/playwright/review-plan-start-ignored.png)。

原因：对话执行分支把 `workMode() !== 'plan'` 作为前提，连已确认后的明确开始指令也一并排除。

影响：同一个清晰的开始意图，按钮可用、对话不可用；用户无法按持续对话路径从计划转制作。

建议：区别“讨论/保存计划”和“明确开始已保存范围”。后者在计划模式也应进入公共执行入口；多项范围含糊时先澄清，不重新回到泛化的制定计划回复。
