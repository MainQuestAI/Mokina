## 2. 可以保留的核心判断

采用完整 OpenDesign 的有限 Fork，沿原生首页、项目、文件、预览和运行能力做营销适配。项目持续组织资料与交付物，对话承担协作；不建立第二套工作台、项目实体或成果存储。

首版主线为市场／营销分析与可操作营销方案。两个场景包是默认入口与专业方法，不是两个固定向导；自由提问、已有资料直接开始、讨论后再生成都应成立。HTML 是成果工作面，原始 PDF、Office 文件仍保留原格式。

保留现有设计系统、品牌资产、图片、演示文稿、视频等能力；可以退出首页默认位置，但不因低频而物理删库。手工修改直接保存，Agent 局部修改形成候选，采用由用户决定。保留固定引用、指定版本交付、后台归属和重启恢复。

## 3. 必须进入计划的修正

| 项目 | 复审发现 | 对开发计划的修正 |
|---|---|---|
| 版本与候选（F07/F08） | 上游有快照、摘要、父版本和锁；但 `createProjectFileVersionUnlocked` 保存后直接把 `currentVersionId` 指向新版本。基础能力不等于未采用候选语义 | 在原版本库中补候选保存与采用提交；模型写临时工作输出，不能先覆盖当前稿再回滚。采用必须检查基础版本，并处理重复提交、取消和失败 |
| 指定版本导出（F08） | 部分接口支持历史 HTML；standalone HTML 带 `versionId` 则明确返回 409。另一路 inline 导出读取历史主文件，但相关资源仍从当前项目读取 | 首版营销模板优先自包含 HTML；仍有外部本地资源时，保存该版所需资源快照。历史正文、图表数据、图片和 PDF 使用同一版，不把“参数存在”视为全部完成 |
| 资料与上下文（F04） | PDF/DOCX/PPTX/XLSX 有预览读取路径；PDF 失败会返回提示文本。API 附件上下文有限额，且不等于 Codex CLI 实际输入 | 分开记录已上传、已解析、选入请求、实际读取、被成果引用。失败提示不可作为资料正文；截断与未读部分要可见。首轮按 Codex 主通道核验 |
| 营销运行绑定（F05/F06） | OD Next 与 legacy 路径并存；显式场景选择与自动默认选择可走不同路径 | 先验证一个稳定营销场景绑定，再做首页入口。记录实际 prompt/Skill/reference；不能只改一个 markdown 文件就宣布四类入口生效 |
| 选择性接续（F09） | 固定片段预览与运行环境是两层要求。新会话若继续拥有原目录、历史 session 或全项目工具上下文，仍可能带入未选择内容 | 默认使用新的原生项目工作空间承接严格接续，自动命名、无需建项目表单；仅带固定片段与显式背景。不挂接原项目目录，不恢复原模型 session；核验工具实际读取范围 |
| 本地产品边界（F01） | 商业组件、更新和账户调用分散在宿主与运行层，隐藏入口不能证明调用停用 | 停用 Mokina 本地版的上游充值、商业云、促销、遥测和自动升级触发；保留模型授权、localhost 鉴权和数据隔离。按实际出站请求检查，不做全仓关键词删除 |
| 旧代码迁移 | 旧 worktree 有解析、片段合成、引用、版本和 PDF 能力，也有独立 `/mokina` 壳与专用运行策略 | 按能力迁移和重测；不整包套旧 patch。保留历史工作区和数据，旧壳不接回主入口，专用代理／隔离机制先评估宿主是否已有等价能力 |
| 完成标准 | 正文没有把源码启动、桌面运行、安装包与用户试用完全拆开 | V0.0.1 定义为 macOS 本地源码可复现、原生桌面与真实 Codex 可用；Web 用于调试验收。全平台安装包和自动更新不作为首版前置条件 |

其中前两项是本次发现的明确源码行为，其他项是据源码与产品要求形成的实施修正。不存在要求重选底座的证据，但也没有“已经运行通过”的证据。

## 5. 推进结论

**可以开始具体开发计划，无须再开一轮产品定位或底座竞选。**首先用原生宿主验证运行绑定、候选不覆盖和固定接续；这些验证直接产生可保留的代码，不另建一次性原型。随后接入两类营销能力并完成真实工作路径。
