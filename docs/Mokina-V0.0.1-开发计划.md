## 1. 要交付的版本

在完整 OpenDesign 原生产品上运行的 Mokina：用户能够提供自己的资料，讨论市场问题或营销目标，生成可读、可改的 HTML 分析／方案，局部修改并采用，选定结论继续工作，导出指定版本，关闭后第二天继续使用。

首轮支持 macOS 本地个人使用，Codex 为主验收通道；保留其他上游模型适配，不宣称全部认证。保留 Web、daemon、Electron；先在 Web 开发，再以原生桌面完成最终使用路径。交付源码、锁文件、启动说明、两个场景包、真实样例和验收记录。暂不要求全平台安装包、签名公证、自动更新服务或云端账号系统。

V0.0.1 是本轮产品版本；历史资料中的 v0.3 是前期设计/实验编号，不据此宣称功能倒退或旧实现已完成本版。

## 4. 逐项实施任务

### T01 固定完整宿主与复现入口（F01/F10）

**输入与落点：** 固定上游、`package.json`、锁文件、`tools/dev`、上游根及分层 `AGENTS.md`，本版运行说明。

**实施：** 导入完整源码；记录 upstream SHA、实际 Node/pnpm 版本；使用独立空数据根运行 Web/daemon 与桌面。先保留原生产品状态，确认可以创建原生项目、连接 Codex、生成和重开一个 HTML。记录基线缺陷与后续改动，避免把上游失败算成 Mokina 修复成果。

**完成：** 干净安装可启动；真实运行产生可读文件；关闭重启能重开；现有用户数据未被改写。缺少 Codex 授权时明确要求用户完成正常登录，不复制或打印凭据，其他离线工作继续。

### T02 提前验证三个关键接口（F06/F07/F09）

**落点：** daemon prompt/strategy 选择、原生 project run 链、`project-file-versions.ts`、原生文件预览动作、接续上下文构建。

**实施：** 在原生宿主用极小样例验证：①显式营销场景能持久绑定，并在首轮/继续/修订/接续实际加载；②模型只产出章节替换，宿主保存候选时不推进 current；③新工作只获选定摘录，无原项目目录和旧 session 注入。

**完成：** 形成三个可重复的检查及实际运行输入记录，确认实现位置。不要求先完成营销内容和全部 UI。若必须侵入多个底层模块，先列明必要改动与可复用接口；不自行换底座，也不以提示词规约冒充保存或读取隔离。

### T03 产品身份与本地运行适配（F01）

**落点：** `apps/web/src/App.tsx`、原导航/设置/账户组件、daemon 启动配置、desktop 更新/遥测入口。更新相关修改前读取 `tools/pack/AGENTS.md`。

**实施：** 显示 Mokina 身份；默认走本地个人项目路径。停用上游云账户充值、商业升级/团队席位、促销、调查、推广归因、星数拉取、上游产品遥测和自动更新。保留真实模型授权/BYOK、项目身份、localhost 鉴权、许可证和本地诊断。使用明确产品配置或已有开关，不做全仓品牌字符串替换。

**完成：** 启动/打开项目/生成时，不主动请求已停用的上游商业、遥测或升级服务；模型及用户主动启用的搜索请求照常工作。UI 隐藏与后台调用均检查。只验证相关网络触发，不新建全产品网络治理平台。

### T04 资料进入工作与证据可回看（F04）

**落点：** 原上传与附件入口、`document-preview.ts`、Codex 请求装配、`research/tavily.ts`、原文件存储；旧 `mokina/materials.ts` 只作能力参考。

**实施：** 先覆盖 TXT、MD、CSV、文本 PDF、DOCX、XLSX 的正文/表格读取；沿用上游 PPTX 文本预览并补实际入模检查。原件保留，生成提取结果、格式限制与来源位置。首次抽取结果要能与原件核对；表格空值、公式未缓存、单位和日期不混淆。

用户能选择本次资料并排除。请求保存选入摘录及定位，不向界面承诺仅选中某文件却给模型整个排除目录。上传、解析、传入、实际读取和引用分别记录；对于 CLI 文件读取，通过工具记录和可核对事实证明。大文件截断、扫描 PDF 无文本、密码保护、解析失败明确显示，不把错误提示当资料正文。

市场研究复用 Tavily 或目标宿主现成可用研究通道。先读取实际配置状态，不泄露 key；至少取得一条真实来源并保存 URL、访问时间、支持结论的摘录，标明摘要与全文读取的区别。未配置时仍可基于用户资料分析，但不能算“联网研究验收通过”。

**完成：** 用只有资料中才有的产品约束验证结果；排除文件中的独有标记不得进入请求/工具读取/结果。换输入事实后，分析与方案实质改变。来源更新不改已引用摘录。

### T05 两个营销场景包与稳定运行绑定（F05/F06）

**落点：** 原 scenario/Skill/plugin 配置、相关 reference；daemon prompt 路径。按目标版本插件规范创建包，不假定任意目录都能被加载。

**实施：** 增加两个独立场景包，沿用原视觉营销能力：

| 场景 | 必须形成的判断 | 最小 HTML 表达 |
|---|---|---|
| 市场／营销分析 | 问题口径、比较维度、关键发现、证据与推断、业务含义、局限 | 结论、比较矩阵、必要图表、可展开来源 |
| 可操作营销方案 | 目标/KPI 假设、受众与方向、行动/渠道、预算与周期、取舍及验证 | 目标到行动的对应关系、预算/周期表、方向比较、待验证项 |

共同 reference 定义稳定章节标识、来源引用、图表数据、打印样式与局部操作结构。尽量自包含 HTML/CSS/SVG，不为每份报告引入新的构建工程。营销理论按任务调用，不强制填完所有框架；参考 `research-decision-room` 的证据组织方式，重写不适用的设计研究语义。

采用 T02 验证过的显式场景绑定；如果它进入 legacy，则只在该路径补齐营销规则，不全局关闭 OD Next，也不要求同时重构所有 BYOK 镜像。自由提出营销问题仍能使用默认营销方法；用户主动选原上游能力时尊重该选择。Ask/讨论不得自行生成或改写成果。

**完成：** 首轮、项目内继续、章节修订、选择性接续四条路径均记录实际加载的场景及 reference。两类成果都真实生成、结构与判断有区别；新会话没有无关画布尺寸/视觉风格向导。

### T06 原生首页与项目中的成果优先（F02/F03）

**落点：** `HomeView.tsx`、`ProjectView.tsx`、`FileWorkspace.tsx`、现有最近项目与工作区状态；不创建 `MokinaWorkspace` 替代组件。

**实施：** 首页保留自由目标输入、上传、最近项目，增加两类营销入口；其他能力放入“更多能力”。直接开始时沿原生流程自动形成项目，不增加建项目表单。

无成果时以讨论为主；打开成果后预览占主要空间，对话可收起。项目重开恢复上次交付物；没有恢复记录时显示现有成果/资料，没有成果则回到输入。资料、成果、相关资源只增加用途显示，不另建存储实体。计划、来源、版本按需展开。保留草稿、查看版本、滚动位置及后台任务归属。

**完成：** 不翻聊天可从项目找到成果；1440×900 和 1280×800 下阅读、对话、文件切换可用；手工草稿与另一运行的结果不互相覆盖。原有设计/媒体入口仍可到达。

### T07 手工保存与章节候选/采用（F07/F08）

**落点：** 原编辑选区/编辑面板、文件版本库、文件写入路由、运行完成处理。复用旧 `references.ts` 的片段替换和越界校验思想，适配现有 DOM 定位。

**实施：** 手工内容编辑直接保存为修订；修改前保留基准版本。AI 修订绑定原文件、基础版本、稳定章节标识和用户要求；只输出所选章节替换，由宿主合成候选。候选在原版本机制内保存，不推进 current、不写原稿；查看与采用分离。

采用时在文件锁内校验基础版本和当前内容，完成当前文件与版本元数据的一致提交。重复采用不重复生成版本；同一章节或基础稿已变化时提示冲突，保留双方内容，让用户重新修订或明确处理；首版不做通用自动合并器。运行取消后迟到输出不提交当前稿。

模型运行使用临时候选输出位置，不能拥有通过普通写文件路径覆盖目标当前稿的权限；由 T02 确认如何使用宿主既有运行边界。不能靠结束后的 diff 检查恢复已经丢失的手工内容。

**完成：** 保留预算和周期只改渠道章节；范围外内容不变。采用前当前稿不变，放弃候选无副作用；同时手工编辑后晚到候选不能覆盖新稿。中途写入失败/进程中断后无文件与 current 不一致。

### T08 历史查看与指定版本 HTML/PDF 导出（F08）

**落点：** 原版本面板、成果卡动作、`import-export-routes.ts`、desktop 导出器及版本资源读取。

**实施：** 分清当前稿、历史版本、未采用候选；历史成果卡可以“查看当时版本”，继续编辑则回到明确的当前稿。首版两类营销 HTML 以自包含为默认，仍使用本地资源时在版本保存阶段冻结所需资源并记录对应关系。

导出显式读取指定版本，不存在就报错；HTML、图表数据、图片和 PDF 都使用该版本的资源，不混入当前资源或未选资料。先复用原生桌面 PDF 导出，不默认移植另一套 Chrome 服务；Web-only 未就绪时按钮说明依赖而非返回假文件。多页长报告打印样式纳入场景 reference。

**完成：** 旧版正文与配图更新后，导出旧版仍是旧内容；当前稿、旧稿、候选各自对应正确。HTML 可在应用外打开，PDF 无关键截断；缺失版本、缺失资源、桌面导出器不可用均明确失败。

### T09 选择性接续（F09）

**落点：** 文件预览选区动作、原生创建项目/请求草稿入口、固定引用读取、运行上下文装配。

**实施：** 选择章节或结论后预览片段、来源版本、必要品牌/目标背景；可删除条目。确认后自动创建新的原生项目工作空间并填入请求草稿，用户发送才执行。项目名自动建议，可后改；不增加设置向导。

只保存所选内容及来源定位，宿主负责回看源版本；模型拿到的是摘录，不是整个来源项目路径。新模型 session、目标工作目录、linked dirs、历史消息和工具资源均核对，不继承原项目的读取授权。如果用户想在同项目继续普通讨论，保留原操作，但不把它标成“仅带所选”。

**完成：** 源文件后来修改/删除不改已保存的接续摘录；来源不存在不能回退整份或最新稿。未发送时无模型运行。实际请求和工具读取无未选文件独有标记；当前品牌约束能随显式选入的背景生效。

### T10 运行、切换、取消与恢复（F10）

**落点：** 宿主 run 状态、SSE/重连、项目视图恢复、保存草稿，不另造任务引擎。

**实施：** 在 T01 起持续验证真实进度、取消、失败、断连和重开。切换项目不能把前一个异步响应放进新项目；完成后只更新所属项目，不抢屏。保存状态以服务端写入结果为准；取消与断连不伪装成功。重启恢复草稿、成果和历史；无法恢复正在执行的进程时明确中断并可重试。

**完成：** A 项目运行时在 B 项目编辑，A 完成不改 B；取消后迟到结果不采用；中断保存可恢复一致状态。沿用既有自动化测试，补行为缺口，不因为“复用”跳过真实 UI 检查。

### T11 最终验收与可复现交付（覆盖 F01–F10）

**产物：** 源码与固定上游记录、锁文件、两个场景包、启动和依赖说明、脱敏样例、验收表、已知限制。记录实际支持格式、搜索配置条件和主模型版本；不携带凭据、用户真实资料或测试缓存。

**验证：** 执行目标上游要求的 `pnpm guard`、`pnpm typecheck` 和与修改包对应的测试/构建；Web E2E 沿用上游 harness。完成真实 Codex、浏览器、桌面操作与干净目录复现，不能仅用 Mock 或旧实验日志抵扣。

**完成：** 下节验收通过；未通过项写明具体能力和影响。模型/检索凭据属于真实外部依赖，有缺口就记录未通过，不静默缩小完成标准。

## 5. 最小数据关系与行为边界

这些是要保持的关系，不要求新建五张表；优先落在宿主已有类型、文件和元数据中。

| 对象关系 | 最少要保留的信息 | 不可违反的行为 |
|---|---|---|
| 项目与文件 | 原项目身份、文件路径、用途 | 不重复建立营销项目/资产库 |
| 营销场景 | 场景 ID、实际加载版本、任务意图 | 换页面或继续工作不能悄悄换方法；普通讨论不写成果 |
| 资料依据 | 固定摘录、来源定位、读取范围及限制 | 来源变化不改旧引用；“上传”不等于“已使用” |
| 候选修订 | 基础版本、章节标识、候选版本、所属运行及状态 | 候选不推进 current，采用有冲突检查 |
| 接续草稿 | 所选片段、来源版本、必要背景、目标项目 | 未发送不执行；不继承整个来源上下文 |
| 导出 | 目标版本、该版资源、格式 | 不静默换最新版，不混用当前资源 |

内部可以使用内容摘要辅助一致性校验；用户不需要确认 SHA/Hash 或每次编辑审批。首稿由用户要求生成后可成为当前稿，既有成果的 AI 修订必须走候选。新成果生成与修改旧稿要有明确目标。

## 6. 验收脚本与通过标准

准备一个合成营销项目，避免混入客户数据：品牌与产品事实、目标/KPI、预算/周期、渠道限制、两份有冲突的新旧资料、一个小型表格、一张可用图片。再准备 B 组事实，改变价格、受众、预算和渠道限制。每类导入格式加入最小测试样本；联网研究另用公开问题，不要求所有任务搜索。

主任务：先讨论新品上市方向，不生成文件；用户要求后生成方案。另从市场问题形成分析，再选择两条结论接续为方案。两条入口可以独立结束。

| 编号 | 实际操作 | 通过标准 | 证据 |
|---|---|---|---|
| A01 | 全新数据根启动，连接 Codex | 原生 Web/桌面可用，无上游商业账户依赖 | 启动日志、运行 ID、实际文件 |
| A02 | 上传/预览/选择资料，替换为 B 组 | 输入约束改变结论；未读与截断可见 | 提取对照、请求/工具记录、两组成果 |
