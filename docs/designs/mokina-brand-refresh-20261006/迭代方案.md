# Mokina 品牌与 UI 设计体系整体更新方案

日期：2026-10-06。状态：盘点与实施建议，待审阅；本轮未修改产品代码、未发起 PR、未更换安装包。本文将已签收产品、独立视觉原型和 Logo 设计资产合成一条更新路线，不将原型验证当作产品验收。

## 1. 目标与结论

本轮目标是让用户从安装、启动、开始工作、与 Mokina 对话，到阅读、修订、绘画标注、导出成果，都接触同一套品牌和界面语言。

建议分五步实施：**品牌母版与替换清单 → 设计变量与图标组件 → 核心页面迁移 → 绘画/桌面/导出补齐 → 同一安装包验收**。复用当前产品的数据、运行、版本、恢复机制，把 OpenDesign Cloud 中已经设计好的页面与组件迁入现有 React 工作台。独立原型的 localStorage、示例运行逻辑不进入产品。

已有材料足以开始制定实施 Spec。品牌图形沿用用户已选择的原 A 饱满抽象轮廓；最新 SVG 精修版作为母版候选，其细节尚未收到用户最终确认。界面沿用现有中性玻璃设计，黑白 Logo 与少量蓝色操作强调可以共存，不需要重新寻找一套品牌颜色。

## 5. 目标设计体系

### 5.1 品牌资产规则

采用原 A 饱满、不对称、柔软的抽象图形。无须添加字母 M 或“智能/增长/协作”寓意；不添加发光、彩色渐变或重复旋转动效。精修 SVG 尚为候选，落地前用首页、对话头像、Dock 三个真实场景确认一次。

建议资产目录 `apps/web/public/mokina/`，提供 mark、wordmark、lockup 以及各平台派生资源；最终路径随仓库现有约定确定。提供 `MokinaMark` 与 `MokinaWordmark` 的小型共用组件，不引入品牌配置框架。主题继承 currentColor；加载型图片提供黑白两版。图标不得拉伸，留白与显示尺寸以同一母版定义。

小尺寸单独验证 16/20/24/32px，对话头像验证 20/24/32px，应用图标验证各实际目标尺寸。若凹口因留白过多消失，只调整光学校正版的占比，不改变整个品牌母版。系统 app icon 的承载底形与裸品牌 mark 分开交付。

### 5.2 界面变量与材质

| 类别 | 迁移目标 | 边界 |
|---|---|---|
| 颜色 | 原型白/中性灰环境、黑色正文；操作蓝参考 `#0071e3`，强调蓝参考 `#2997ff` | 这是现有原型色板，不是本轮新增品牌主色；不再沿用发送按钮 `#00ff08` 作为默认品牌表达 |
| 语义色 | 成功/警告/失败/链接单独定义，并配图标与文字 | 不把所有绿色替换成蓝色；成功色与旧品牌绿需分类 |
| 字体 | 系统字体栈、中文优先可读；正文、辅助信息、数字和代码有层级 | Logo 字标为路径，不能替代 UI 字体；不打包未经授权专有字体 |
| 间距/圆角 | 从当前原型最终样式提取导航、容器、控件三档 | 不从早期文档的单一16px数值推全站；避免层层大圆角卡片 |
| 玻璃 | 导航、工具条、输入与弹出层；正文和表单实底 | 文字不参与折射；失效、减少透明度或性能不足时回退实底 |
| 动态 | 160ms 可作为既有交互基线，状态动效克制 | 减少动态时关闭非必要运动；动画不能掩盖真实等待或失败 |
| 主题 | 黑白 Logo 分别适配浅/深背景；在生产已支持的主题中验证 | 原型浅色通过不等于深色可用；不扩大平台支持承诺 |

建议在现有 tokens 上增加必要的 Mokina 语义别名，统一应用入口；清理已证实冲突的旧品牌变量。避免维护一套新的庞大、重复主题系统。

### 5.3 图标语义表

| 分组 | 本轮必须核对的语义 | 样式原则 |
|---|---|---|
| 导航 | home、projects/folder、recent、search、settings、more、back | 同一线性风格，活动状态不靠换不相关图形 |
| 输入 | attach、send、stop、retry、remove、voice（仅现有可达时） | send 与 stop 在同一位置保持清楚区分；不把 Logo 用成发送箭头 |
| 工作成果 | file、edit、compare、adopt、history、export、download、continue、source、link | “采用候选”与“保存”不可用同一无说明图标；导出与下载文字明确 |
| 状态 | idle、running、success、warning、error、unknown、rejected、conflict、readonly | 未知不是失败；拒绝不是已取消；历史不是当前；必须配可读标签 |
| 绘画标注 | select、hand、pen、eraser、shape、arrow、text、undo、redo、zoom、clear、save、close | 沿用工具习惯与快捷键；更新自有边框和图标，不改底层笔画/历史算法 |
| 品牌/来源 | Mokina、执行 Agent、模型、编辑器、客户品牌、文件类型 | 六种身份各自表达，不相互冒用 |

基础建议：24×24 设计网格，16/20/24px 应用尺寸，1.65px 作为原型线宽参考，按小尺寸可读性调整；图形线宽与按钮点击区域独立。移动关键控件以现有原型44px目标为参考，桌面密集工具条提供合理命中区、tooltip 和键盘焦点。

绘画编辑器中由第三方引擎管理的控件，优先用已有扩展与主题入口；不通过批量改内嵌 SVG 或脆弱选择器重写整套工具栏。若无可靠扩展口，本轮统一外壳，保留引擎工具图标并在清单说明。

## 6. 迁移方式与功能保护

1. **先冻结参照**：Logo 母版、原型入口、样式顺序、页面截图与 SHA；最新精修字标须保留原 SVG 比较入口。
2. **建立组件对应表**：原型每个页面映射现有组件，不复制原型状态存储或模拟接口。
3. **先贯通一个真实纵向场景**：首页 → 真实资料 → 对话生成 → 成果 → 修订候选 → 显式采用 → 指定版本导出；验证身份与图标体系后再覆盖其余页面。
4. **替换视觉接线，不动事实含义**：pending/unknown/rejected、版本与候选身份、冻结输入、clientRequestId、恢复 journal 等继续使用现有契约。
5. **共用资产更新桌面**：splash、Web、Dock、DMG 同源；通过 Mokina 产品 profile 选资源，不全局覆盖第三方上游资源与许可。
6. **回滚按提交而非数据**：每批可独立撤回样式/组件引用；不迁移用户数据，不重置草稿/项目/历史版本。
