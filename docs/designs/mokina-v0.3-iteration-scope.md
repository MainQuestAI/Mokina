# Mokina v0.3 详细迭代范围：OpenDesign 复用路线

日期：2026-09-20  
对应议题：MOK-1  详细迭代范围  
状态：范围收敛完成，供 MOK-3 拆解详细功能规划。  
性质：产品与工程边界文件，不代表 OpenDesign 已完成构建、运行或浏览器验收。

## 1. 结论

Mokina 下一轮不继续扩展当前 V6.2 单体原型，也不重新搭建一套前端、后端、会话、运行和文件系统。采用 OpenDesign 固定基线作为工作台与本地运行底座，在其现有 Web、daemon、contracts、文件工作区、版本、预览、导出和 CLI/runtime 能力上做营销适配。

建设重点从“补更多营销按钮”调整为四件事：

1. 把营销工作目标、资料依据、成果和运行状态接入同一工作边界。
2. 把分析、策略、精修和交付组织成可读、可改、可比较、可接续的成果，而不是只显示聊天文本。
3. 把固定版本、候选、采用、引用和失败恢复做成真实契约，不用提示词或演示状态代替。
4. 用少量真实营销场景验收 Codex 路径，再决定是否扩大能力包、格式和运行底座。

本文件不重新讨论已确认的底座方向；它只明确本轮做什么、沿用什么、删掉什么以及暂缓什么。

## 3. 产品工作边界

### 3.1 工作身份

用户打开或新建一项工作，先输入目标，可选地加入资料、已有背景或明确成果引用。工作不强制绑定项目、SKU、Brand Kit 或完整计划。长期背景、品牌规则和本次要求分别保存，不能把本次临时语气自动升级为永久品牌规则。

工作区沿用 OpenDesign 的成熟形态：左侧切换工作，中间对话，右侧成果；计划、依据、版本和运行详情按需展开。它们属于同一工作，不另建营销专用的 Work、Session、Task 三套生命周期。

### 3.2 两个自然入口

| 入口 | 首轮行为 | 明确不做 |
|---|---|---|
| 问题入口 | 用户提出市场、用户、竞品或产品问题；可选择资料；明确执行后形成可读分析/策略报告 | 不强制搜索、不强制建项目、不把搜索摘要当已确认事实 |
| 任务入口 | 用户提供品牌、产品、目标或 KPI；形成 Brief、方向和可执行营销方案 | 不要求每个任务都填写产品型号、市场、语言、渠道等上市字段 |

两条入口共用工作、资料、运行、成果和版本。报告是营销方案的阅读与交付视图，不把“报告”发展成另一套事实库或工作生命周期。

### 3.3 三种行动语义

- **Ask**：解释、澄清或比较，不改成果。
- **Plan**：讨论目标、交付、输入、排除项和顺序；保存计划不制作。
- **Execute**：用户明确开始后，固定本次输入并运行；运行结果先成为草稿/候选，不自动采用、发布或发送。

行动模式不是三张页面。一个工作可以直接 Ask → Execute，也可以先保存 Plan；只有范围含糊或存在多个待执行项时才要求用户选择。

## 4. 首轮必须覆盖的用户场景

以下场景是 MOK-3 的功能拆解输入。每个场景都要写清输入、用户动作、成果、版本/来源行为和失败处理。

### S1：从问题到分析/策略成果

用户输入一个实际问题，选择或上传少量资料，先讨论，再明确执行。Agent 使用真实 Codex 路径读取固定输入，形成可阅读的分析或策略成果，包含结论、依据、假设、局限和下一步建议。

验收重点：新工作不自动带入演示样例；没有资料时说明缺口；事实、推断和待验证目标分开；来源变化不会改写已生成版本；运行失败不产生假成果。

### S2：从品牌/产品/KPI到营销方向

用户提供品牌背景、产品事实、目标或 KPI，选择需要的专业方法，生成一个或多个方向。方向应能继续形成 Brief、Message House、渠道内容或行动建议；不同方向可以并存，不能用“最新同类型成果”覆盖旧方向。

验收重点：可只使用已有背景开始；不把缺少图片当成文字工作阻断条件；KPI 计算说明口径和数据不足；需要研究时可选择研究，不把搜索变成必经步骤。

### S3：成果阅读、局部编辑与候选比较

用户打开成果并阅读同一指定版本。普通手动编辑直接形成新的工作修订；Agent 局部修改必须绑定成果 ID、基础版本和稳定段落/条目 ID，保存为候选。用户可以比较、采用、不采用或暂缓，原版和已采用版保留。

验收重点：只改选定段落；“第三条更简洁”不能改动其他条目；基础版本已变化时形成冲突候选并提示比较；候选未采用前不能改写当前稿；首次创建不因候选机制增加额外审批。

### S4：资料读取与固定依据

首轮读取 TXT、Markdown、CSV、文本型 PDF、DOCX 正文/基本表格和 XLSX 单元格值；保留原文件、提取结果和位置。运行前生成不可变输入快照，记录所选资料、排除项、版本/片段和摘要校验值。

验收重点：PDF保留页码，表格保留工作表/行列来源；XLSX 公式使用缓存值并明确标记，不执行宏或静默重算；部分读取、无缓存值、扫描页和复杂图表要显示限制；不能用空值或零补齐事实。

### S5：选择性接续到下一项工作

用户在成果中选择指定版本和片段，预览将带入的正文、目标、品牌要求和来源，再确认创建新的工作。新工作只获得选定片段和必要背景，不复制整个项目目录，也不自动发送或执行。

验收重点：来源版本固定；原工作后来编辑时旧摘录仍可查看并显示变化提示；新工作与原工作可并行切换；取消接续不删除历史引用。

### S6：并行工作、取消和恢复

运行期间用户可以切换其他工作。结果只能回到启动它的工作，不能抢占当前焦点；取消后迟到或重复事件不得重新生成成果。刷新或重启后能恢复工作草稿、输入快照、查看位置和运行终态；无法恢复时显示待重试或冲突，不伪造成功。

### S7：指定版本交付

从同一成果版本实际导出 HTML 和 PDF，导出内容与阅读视图、依据说明一致。失败或回退不能静默换到最新版，也不能把未选原始资料打包进去。首轮不承诺可编辑 DOCX/PPTX 交付。

## 5. OpenDesign 复用与 Mokina 适配矩阵

| OpenDesign 现有层 | 首轮处理 | Mokina 需要补的语义 |
|---|---|---|
| Web 工作区、对话、文件/成果标签、预览 | 直接复用交互与状态组织 | 营销入口、当前工作范围、成果类型和中文业务文案 |
| 手工编辑、撤销/重做、局部编辑面板 | 复用编辑框架 | 将段落/条目稳定 ID 接入营销成果，普通编辑与 Agent 候选分开 |
| 文件版本、历史预览、恢复入口 | 复用版本读写和预览 | 扩展基础版本、候选、当前稿、采用指针和固定引用语义 |
| 本地文件、导入、导出和预览 | 复用上游路径并核对真实支持范围 | TXT/MD/CSV/PDF/DOCX/XLSX 读取限制、位置来源、HTML/PDF 指定版本导出 |
| daemon/runtime、CLI、事件、取消/恢复 | 复用既有运行入口 | 固定工作归属、运行输入、临时副本、实际写入边界和迟到事件守卫 |
| contracts、workspace context、运行输入 | 复用契约扩展方式 | 版本/片段引用、不可变输入快照、运行记录和候选保存结果 |
| 品牌体系、模板、Skill/插件加载 | 复用资源形态，不直接安装全部候选 | 五个按需营销能力单元、来源/许可/版本记录和适用条件 |
| OpenDesign 的通用项目/文件组织 | 作为宿主能力 | 不让项目、目录或设计文件替代 Mokina 的营销工作与成果关系 |

五个能力单元按需组合，不新建工作流引擎：

1. 背景理解与 Brief：区分用户确认、公开信息、推断和缺口。
2. 市场与竞争分析：按问题选择用户、市场、竞品或产品分析方法，说明来源、口径和局限。
3. KPI 拆解与策略方向：从目标、预算、周期和产品条件推导行动与验证，不把假设转化率写成事实。
4. 可视化报告组织：将分析和策略组织为同版本可读 HTML/报告，不另造事实正文。
5. 局部精修与方案比较：绑定成果/版本/段落形成候选，比较和采用由宿主契约保障。

## 6. 当前 Mokina 功能的取舍

### 保留为行为基线并迁移

- Ask/Plan/Execute 的边界，保存计划不制作。
- 当前工作、项目汇总和全局成果的范围区分。
- 资料选择、排除、输入快照和来源固定。
- 多成果、多版本、手动修订、候选比较、采用/不采用/暂缓。
- 指定片段接续、来源返回、并行工作和后台结果归属。
- CSV 的真实计算、口径说明和无效数据阻断。
- 取消、迟到事件、刷新恢复、未知成果类型和失败信息的可解释处理。
- V6.2 已验证的专业场景和历史数据作为回归素材，不把旧 UI 当作宿主。

### 从新产品主路径中删减或降级

- V6.2 的 SpaceMaster/冰箱/德国上市样例不作为新工作默认上下文，只保留显式示例入口。
- 产品上市的完整产品字段、SKU、市场、语言、渠道强校验，不再阻断一般品牌/研究/分析工作。
- 旧项目唯一交付计划、固定 FABE/MH 依赖和 `BATCH_ORDER` 不升级为通用营销流程。
- CL、正式审批、合同、资产上传和外部发布只保留为明确的专业场景/交接边界，不阻断普通内部草稿。
- 旧单体 V6.2 shell、`src/marketing-desktop/` 的独立状态存储和关键词情景生成不继续扩张为第二套生产系统。

### 本轮新增

- OpenDesign 固定基线的可复现本地 Web 启动和依赖/许可记录。
- 工作—资料—运行—成果的统一归属和固定输入契约。
- 成果版本状态：工作当前稿、候选、采用版本、固定引用互不混淆。
- Agent 临时副本、输出校验、可恢复采用提交和迟到结果保护。
- 五个按需营销能力单元及其输入/输出/检查边界。
- 首轮真实 Codex 验收、资料格式读取、HTML/PDF 指定版本导出。

### 明确延后

- 桌面安装包、签名、公证、自动更新和托盘能力。
- SaaS 托管、企业权限、审批中心、计费和团队协作治理。
- 自动 Skill 发现/安装/改写、Skill 市场和自动进化系统。
- 广告投放、CRM、社媒自动发布、完整 DAM 和外部渠道连接器。
- 扫描件 OCR、复杂图表理解、复杂 Office 版式还原、可编辑 DOCX/PPTX 导出。
- Claude 等其他运行底座与 Codex 同等级的完整验收。
- 在取得性能基线前预建缓存平台、索引库或新的调度系统。

## 7. 首轮交付的最小边界

首轮只有在以下链路同时成立时才算功能闭环：

```text
输入目标/资料
  → 选择并固定依据
  → Ask 或 Plan
  → 用户明确 Execute
  → Codex 真实运行
  → 指定工作内生成可读成果
  → 手动或 Agent 局部修订
  → 比较/采用
  → HTML/PDF 指定版本导出或选择性接续
```

必须具备：

- 本地 Web 工作区可复现启动，OpenDesign 上游依赖和许可边界有记录。
- Codex 至少覆盖问题入口、任务入口、固定输入、局部修订、候选采用、接续、取消和恢复。
- 旧原型的关键行为测试保留为回归，不以旧测试通过替代新底座验证。
- 真实文件上传/读取、实际下载/读回和 1440×900、1280×800 浏览器全流程证据。
- 失败、缺输入、权限、解析限制、版本冲突和运行未配置时显示真实状态，不生成模拟成功。

不作为首轮完成条件：产品发布、商业使用批准、外部渠道上线、专业人工验收通过、全量模型接入或桌面安装包可用。

## 8. MOK-3 拆解要求

MOK-3 应基于本文件拆成可执行功能规划，而不是再次讨论是否从零开发。每个功能至少写明：

1. 所属场景（S1–S7）和用户可见动作。
2. 复用的 OpenDesign 层及需要修改的契约/入口。
3. 输入、输出、版本/来源关系和失败路径。
4. 完成所需的静态/单元、真实 Runtime、浏览器 QA 和文件读回证据。
5. 依赖顺序、可独立交付的最小切片，以及不纳入本项的相邻能力。

推荐拆解顺序：

1. 上游基线、构建启动、许可和数据目录。
2. Work/Context/Run 归属与固定输入。
3. Artifact/Version/Candidate/Adoption 契约及可恢复保存。
4. Web 工作区入口、成果阅读、局部编辑和比较采用。
5. 文件读取、五类能力单元和报告组织。
6. Codex 真实执行、取消/恢复、HTML/PDF 导出和选择性接续。
7. 双尺寸浏览器全流程、质量配对评估、性能基线和交付文档。

## 9. 仍需在实施中核验的事项

本文件已经收敛产品范围，但以下是实施证据，不因文档完成而自动成立：

- 固定 OpenDesign 提交是否能在当前 macOS 环境构建并启动 Web/daemon。
- 上游模型/CLI 配置、文件工具、绝对路径和临时 cwd 是否真的保护原稿。
- 候选保存、采用多文件写入和中断恢复是否具备可恢复一致性。
- 各文件格式实际可读内容、页码/行列定位、公式缓存和导出分页。
- 五个能力包的加载版本、许可、适用范围及真实输出质量。
- Codex 运行、取消、迟到事件、刷新恢复和并行切换是否在浏览器中成立。

这些项目进入 MOK-3 的功能验收和后续实施任务；在取得证据前，不将“可复用”“已设计”写成“已完成”。
