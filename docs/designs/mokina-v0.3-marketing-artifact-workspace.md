## 1. 已确认的核心决定

**策略类工作的核心 Artifact 是“可操作的营销方案”，报告是它自然生成的阅读与交付视图。**

用户先对核心选择回复“认可”，随后同意设计文档作为产品形态基线。2026-09-15 继续补充 To C 开源定位、研究入口、模板个性化及研究接续；第 10 节的具体页面行为是助手据此提出的建议，不冒充已逐项批准。技术实现仍待核验。

**Mokina 是面向个人使用者的 To C 开源项目，服务营销专业工作，不按 To B 定制交付或企业采购定义首版。** Office Hour 使用 Builder 模式。第一阶段重点是理解品牌与当前任务、组合专业方法、围绕逐步形成的成果持续协作。

既有客户项目是用户理解需求的来源，不是 Mokina 的商业定位。不再用客户岗位、采购、支付意愿或企业验收作为本轮前置问题；个人使用与开源传播仍可后续讨论。

## 2. 本轮已明确的方向及原因

| 决定 | 原因及影响 |
|---|---|
| 直接输入目标即可开始，Brand Kit 按需建立 | 长期品牌理解有价值，但不能阻断临时任务 |
| 建立背景时可提供角色、品牌、官网和资料，由 Agent 搜索、整理并沟通确认 | 不要求用户自行编写完整的品牌说明；搜索推断不冒充品牌确认 |
| 岗位偏好、品牌规则与当前要求分开 | “本次更活泼”不能变成所有后续工作的品牌规则 |
| 第一阶段以逐步形成成果为主 | 用户参与方向判断和精修；不是每一步都要批准，也不是必须 One Shot |
| 会话并行属于基础能力 | Agent 运行时用户会推进其他线程；不是被打断后的补救体验 |
| 会话、引用、Fork 等沿用成熟 Agent 机制 | 不为营销重造会话系统；跨会话调用可作为增强能力，实际底座支持待核验 |
| Ask／Plan／执行是同一工作区的行动模式 | 区分探讨、规划与修改，不做三个页面或强制阶段 |
| 下一步建议把完整请求带入输入框，由用户发送 | 方法辅助目标表达；建议不自动变成待办，不自动执行 |
| 专业方法、行业视角与可个性化模板共同支撑内核 | 模板可封装为 Skill 或提示词；分析维度与指标口径影响研究本身，不只影响排版 |
| 核心成果可以直接编辑，也可以选中局部交给 Agent 修改 | 两种操作作用于同一成果，版本和改动可回看 |
| 项目管理、复杂任务编排不是第一阶段中心 | 可选组织不主导日常工作；以后可以增加看板和自动化 |
| KPI 拆解与已有背景、必要研究相互校验，再形成策略 | KPI 由谁设定不影响此能力；搜索不是必选步骤，拆解不是平均分摊数字 |
| 内容不是唯一中心，但必须能产出并继续使用 | 自行生成和外部制作都可能进入营销工作，不限定渠道或文件类型 |

## 3. 第一阶段聚焦与通用 Agent 的关系

产品重点是**结合工作上下文开展营销分析、拆解与策略制定**。用户提出的首次使用示例是完成一份市场分析报告，例如“过去 3 个月宠物食品行业最流行的产品品类是什么”。这是产品交互案例，不是要求本轮实际调查宠物食品，也不限定产品为报告工具或宠物行业工具。

研究报告可作为入口和后续工作的依据，但不是必经上游。用户可以从已有报告、内部资料、产品特点、品牌故事或当前 KPI 直接开始；不要求这些输入全部齐备。

通用基础尽量复用会话、执行、文件、版本等成熟机制；专业化重点放在：

1. 品牌背景与当前约束能够实际进入工作。
2. 专业方法按问题组合，用户不必自行拼接技术流程。
3. 成果中的结论、方向和动作有明确身份，能被选择、比较、修改和引用。
4. 结果在工作过程中可视化，最终自然形成专业交付，不要求重新整理聊天。

这是产品分工，不是声称通用 Agent 无法完成这些事情，也不承诺研究质量已超过 ChatGPT Deep Research。价值重点是专业方法、行业视角和内部背景如何支持后续判断，而非仅汇总 Web search 结果。

不做以下扩大：完整投放与归因平台、外部发布、全套项目管理、自动运行所有营销方法、所有多媒体格式的原生编辑器。首稿可用性和成套交付质量仍是目标，但本轮先定义产品，不以效果实验取代形态讨论。

## 4. 信息架构与工作区

### 4.1 三种角色，不新增竞争性的工作系统

- **会话是工作位置**：沿用会话身份，保存当前讨论与运行；“营销工作”是用户语言，不新增另一套独立 Work 生命周期。
- **成果是操作对象**：同一会话可以有主成果及关联成果，成果也能被其他会话引用。
- **品牌是可复用上下文**：无品牌任务仍可开始，品牌关联不是项目归属的替代品。

项目作为可选组织方式。成果分类不做四个强制入口，也不把每次对话或每个成果版本放成一项全局工作。

### 4.2 工作区布局建议

| 区域 | 默认内容 | 行为 |
|---|---|---|
| 全局左栏 | 新建、最近和固定会话、真实运行与关注状态；品牌和方法辅助入口 | 默认可见、可收起；切换不终止其他会话 |
| 中间对话 | 目标、讨论、问题、成果操作回复、下一步建议、行动模式 | 对选中对象提问或修改；输入和选择随会话恢复 |
| 右侧成果 | 当前成果、版本、比较与编辑；关联成果标签 | 成果优先分配空间；无成果时不占满空面板 |

目标与约束、计划、资料、所用方法通过紧凑摘要及按需面板查看，不默认增加第四条常驻栏。

Mokina 软件界面保持稳定的产品身份。客户品牌影响成果呈现，不把整个软件换成客户外壳。具体色彩、字体、尺寸、响应式和组件仍待视觉设计。

A 运行时可以切去 B；A 返回只更新自身状态和结果，不抢走 B 的画布、输入或焦点。左栏区分“正在处理”“需要回应”“有新结果”；执行结束不自动等于营销工作完成。

### 4.3 三种行动模式

- **讨论（Ask）**：解释、提问、探讨，不修改工作稿。
- **规划（Plan）**：整理 Brief、方法、范围与交付安排；可以保存计划，不因保存就开始调研或制作。
- **执行（对应 Design）**：按当前要求调研、制作或修改，产生实际结果与版本。

模式不是步骤。资料不充分时可以讨论或形成明确标注缺口的草稿；关键事实未知时不编造。执行模式仍需识别操作对象和否定要求，不能将任何提问都当作修改授权。执行模式的最终显示名称待定。

## 5. 核心 Artifact：可操作的营销方案

### 5.1 方案里有哪些内容

| 内容 | 展示 | 专业操作 |
|---|---|---|
| 工作 Brief | 目标、KPI、预算、周期、主题及未知项 | 补充、修改、讨论约束 |
| 目标拆解 | 关键驱动因素、可能路径、假设和待验证项 | 调整、解释、提出研究问题 |
| 研究发现 | 市场、用户、竞争、产品分析与资料依据 | 查看来源、选取结论、质疑或补充 |
| 策略方向 | A/B/C 主张、表达、资源要求及取舍 | 并排比较、深化、组合 |
| 执行安排 | 动作、制作要求、资源、节奏和衡量方式 | 修改安排，形成关联成果 |

这是策略类成果的内容参考，不是固定表单、必填清单或通用工作流程。未形成的部分不以空模板冒充完成。

KPI 拆解与研究往返进行，不把所有目标硬套进同一转化漏斗，不假造转化率或因果关系。研究可以改变实现路径；调整用户给定 KPI 或预算时应提出建议，不静默改掉原要求。

### 5.2 工作视图与阅读视图

- **工作视图**：围绕当前任务展示方向对照、证据、局部编辑、关联动作与版本变化。
- **阅读视图**：将同一成果组织为完整、可视化的报告，呈现结论、必要推导、依据、适用条件和安排。

两者面向同一个明确版本，不是各自生成、内容可能失配的两份文档。阅读视图不等于编辑界面的截图；成果模板负责排版和叙事组织。

交付自动成为工作结果的一部分。导出只是带走当前指定版本，不是用户额外发起一次“把聊天做成报告”。本轮尚未确定公开分享、托管方式或导出格式全集，HTML 报告是已讨论的交付方向。

### 5.3 不是无限画布，也不是把一切变成卡片

“可操作”首先意味着用户能准确选择和修改专业内容，不意味着首版必须建设自由拖拽白板或节点编排器。适合长文的内容仍可长文阅读，适合表格的数据仍保持表格。

拟从少量可识别的段落、方向和条目开始。稳定身份、版本和引用的具体结构将在技术设计中核验，不在本轮另造复杂营销本体或通用编辑框架。

## 6. 多类型成果如何共存

| 类别 | 例子 | 适合的主要操作 |
|---|---|---|
| 研究与分析 | 访谈洞察、竞品研究、运营分析 | 依据、口径、分组、结论选择 |
| 策略与创意 | 品牌方向、传播主题、活动方案 | 对照、取舍、组合、深化 |
| 内容与素材 | 文案、内容组合、视觉或视频 | 实际呈现、局部修改、变体和版本 |
| 计划与安排 | 排期、传播安排、制作 Brief | 条目、顺序、日期与跨项一致性 |

分类用于匹配工作面，不要求用户先选类别，也不是首版承诺同时接入所有媒介。

统一保存、版本、来源、选择和导出能力；不同内容使用合适的编辑方式。某类文件无法原生编辑时如实显示能力边界，可提供预览、批注、外部编辑或文件替换，不把整文件替换称为语义级局部编辑。

外部成果也可进入关联工作；来源说明区分导入与生成。首版实际支持的外部格式、可编辑范围和替换后的引用处理列入后续原型/技术定义。

## 7. 感性、理性与版本关系

创意可从故事、品牌经历和热点开始，分析也可独立完成，不新增感性/理性两套行动模式。

成果应区分事实依据、分析判断、待验证假设和创意表达，但不强制每句话加标签。用户在关键判断处能够查看依据与不确定性。可解释的推导是分析结果及取舍说明，不是模型内部思维链或技术日志。

版本机制的产品原则：

- 查看版本不自动改变当前采用方向；历史版本与来源保留。
- 新方向和 A/B 组合保留原方向，并检查组合是否一致，不机械拼接。
- 直接编辑与 Agent 编辑都操作同一成果；撤销、候选、自动保存的精确规则仍待交互细化。
- 修订针对明确成果、基础版本和局部对象，比较说明实际业务变化，而不只给文本差异。
- 引用指向明确版本与选定内容；上游变化可以提示，下游不自动跟随重写。
- 数据变化、口径变化和表述变化应分开；报告完成不冒充 KPI 达成。

这些原则服务可控修改，不把每次微小编辑都变成审批或额外交付流程。

## 8. 一条策略工作的页面过程

以下为说明产品形态的虚构任务，不是客户验收案例或已验证运行。

“结合品牌背景，在给定预算和周期内，形成会员增长策略。”

1. 直接输入目标，按需选用品牌资料；未建 Brand Kit 不阻断。
2. 讨论形成初步 Brief，用户可以修改目标与约束。规划模式可保存范围，不执行研究。
3. 用户明确执行后，Agent 结合已有背景拆解 KPI；仅在当前判断需要时补充研究。可以离开当前会话，其他工作照常推进。
4. 研究发现逐步进入成果工作面；Agent 只就影响判断的关键缺口提问，不要求逐条审核资料。
5. 形成多个策略方向；并排展示主题和表达，也能查看各自服务目标的逻辑、资源要求和假设。
6. 用户选择“保留 A 的受众、采用 B 的主题”；形成可比较的新版本，原方案保留。
7. 通过下一步卡片展开安排或制作 Brief；请求带入输入框后发送，不自动产生额外任务。
8. 明确方向后形成完整阅读视图与交付版本，呈现依据和衡量方式，不声明真实市场效果。
9. 可引用选定成果继续内容工作，也可以停在当前策略成果；不强制完整链路。

此过程不规定每一步都要确认。若用户只修改已有内容，从对应成果直接开始。

## 9. 专业能力与开源复用

专业环境由品牌背景、营销方法、行业认知、可个性化的分析维度与指标口径、成果呈现和精修共同构成。Web search 等通用工具负责信息获取，不能代替专业分析。

目标输入为主，方法选择是辅助入口。用户看到“竞争分析”“深化当前方向”等营销语言；底层包、依赖和提示词不占据主要界面。下一步建议应说明针对什么成果，选择后请求可编辑，支持点击与键盘，不只依赖 Hover。

用户支持参考和复用 OpenDesign，也不排斥直接改其代码。当前把它作为优先候选，尚未完成主底座选择或能力验证。参考资料是阶段证据，不据此声明其所有交互和扩展点当前都已可用。

后续适配核验重点：会话并行与 Fork、Ask/Plan/执行边界、成果编辑与版本、语义定位、跨会话引用、工作/阅读视图的一致性。优先检查现成机制，再判断配置、扩展或宿主修改的落点；不拼接竞争性的会话、运行和存储系统。

Meta Skill／能力雷达用于持续寻找、推荐、适配相关能力。发现不等于验证可用，不因找到新 Skill 就自动安装或更改当前工作方法；具体自动化范围后续定义。未把任何视频或内容开源项目记作已接入。

### 9.1 个性化模板不是新的一套配置系统

用户可调整研究重点、分析维度和指标口径；它们必须影响研究与结果，而不只是最终报告样式。可以从已有模板起步，也可以通过自然语言调整；不先填写全部配置才开始。

工作引导、方法、参数和成果结构可以封装为 Skill 或提示词，不为每个概念另建一个产品模块。单次报告仍是有资料、时间、判断和版本的成果，不自动变成通用方法。

建议的行为：调整默认只作用于当前工作；用户主动“保存为我的模板”后才跨工作复用。保存范围应能查看，不把私人资料、品牌背景或旧结论作为公共模板默认内容。共享与社区不是当前重点。

指标缺少可靠数据时说明缺口，不静默用讨论热度代替销售表现，不生成无依据的综合排名。时间窗口、分类和覆盖范围应与结论一致。更换模板不把旧成果重新标为按新方法生成。

### 9.2 行业认知与事实的来源不同

行业认知帮助选择分类、渠道、消费行为和竞争比较视角，不只是给通用报告加一段行业介绍。可考虑以带来源和适用范围的资料、行业分析指引和可维护资源提供基础；具体组织方式是待验证建议，不宣称已经有完整行业知识库。

行业通识、当期市场资料、用户内部事实、工作目标和偏好分别使用。用户可以更正背景；一次研究结论不能自动升级成永久行业事实。

研究不足不等于策略必须停下：可以提出明确标注假设的候选，但需要事实才能成立的关键判断不冒充已证实；必要时针对缺口询问或建议补充研究。

## 10. 从已有上下文进入策略：具体交互建议

本节用于下一轮页面讨论。示例不含实际宠物市场发现或排名，不预设一个虚构结论为事实。

### 10.1 入口不是另一个向导

用户在报告中选中内容，点击“用于当前工作”，或直接输入：

> 结合这份报告和我的产品资料，帮我判断有哪些适合自己的营销方向。

输入框附近显示本轮带入的内容，例如“市场报告 v2 · 选定片段”“产品资料”“当前目标”。可展开正文、替换版本和移除，不要求逐条点确认。引用整份报告或只引用片段都可以，尊重用户范围，不一律扩大或缩小。

用户也可以没有报告，直接提供自己的 KPI 或产品信息。此时从同一输入入口开始，不提示先完成搜索。

### 10.2 同会话继续为自然路径，另开工作可选

在当前会话继续时，原报告与新的策略作为不同成果保留，右侧通过标签切换。用户可以明确另开会话或 Fork；不把“开始策略”强制转成新工作，也不复制整个品牌或项目上下文。

另开会话时显示带入摘要与引用范围；引用保留指定版本。沿用成熟会话机制，具体跨会话调用能力仍待底座核验。

### 10.3 Agent 先连接内外部信息，不自动再跑一轮搜索

Agent 结合可用背景解释哪些发现可能适用、哪些不适用、关键缺口是什么。不是把“市场热门”直接变成“本品牌应该跟进”。

按用户所选模式行动：Ask 只讨论；Plan 保存分析安排、不执行新研究或生成策略成果；执行模式按明确目标分析、必要时研究并制作。不因点击引用或更换版本就触发制作。

产品特点、品牌故事、KPI 是可用的不同输入，不要求全部填写。缺失信息只在影响当前判断时追问。无数值 KPI 的品牌讨论仍然有效，不强行量化创意。

### 10.4 右侧呈现自己的策略，关键处可以展开依据

用户主要看到方向、表达及可行安排。需要时展开对应的外部发现、内部条件与适用假设；不默认摆成一张复杂证据图或第四条常驻侧栏。

根据问题需要提出一个或多个方向，不强制每项任务都生成三版。用户选中一个方向解释、改写或与另一方向组合；修改结果保留可回看的版本。详细的自动保存、候选与采用规则沿用本文件待定状态。

### 10.5 来源变化与策略变化分别处理

新策略保存当次实际使用的报告版本、内部资料及必要假设。旧报告不被改写为“已经考虑本品牌”；新策略的判断也不回填为市场事实。

报告出现新版时，已有策略仍保留原引用；提示相关更新，由用户决定是否重做相应分析。引用版本/片段不可用时指出具体缺口，不悄悄换成最新版。

工作视图与阅读视图展示同一策略版本。报告输出是成果的自然组成部分，但不强制用户结束讨论或导出。

### 10.6 这条路径如何成立

后续应在页面中检查：选定引用准确；只有内部背景时能开始；搜索可选；讨论不改稿；计划不制作；策略与原研究各自保留；局部修改与来源可查看；不同会话互不抢占。

研究首次体验和策略接续都可以独立结束。分享、模板传播和社区被后移，不作为此次路径成立的前置条件。
