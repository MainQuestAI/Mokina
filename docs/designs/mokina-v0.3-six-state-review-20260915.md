# Mokina 六状态线框：整体评审与视觉收敛建议

日期：2026-09-15。状态：本轮评审完成，设计建议待用户确认。范围：现有六状态线框，不是产品代码验收或开源底座选型。

## 1. 结论

保留“并行会话 + 持续对话 + 成果工作面”的结构，进入视觉收敛。不要再把后续设计拆成更多流程页，也不要只把灰阶界面换成彩色。

目前最需要推进的是三个方面：让成果正文成为首屏重点；统一编辑、比较、阅读和接续的入口；让品牌约束、专业方法与 KPI 在现有工作面里实际影响判断。

专业性的落点不是一组营销导航名称。用户应能看见：同一条市场线索，在自己的品牌、产品和目标下为何形成这个策略，接着能够修改和复用其中一部分。六张线框已经表达了后半段；对品牌理解、专业方法、目标拆解的呈现仍偏弱。

## 2. 保留哪些设计

- 左侧并行工作入口保留，允许收起；不改成必须进入项目才能工作的结构。
- 中间持续对话，右侧当前成果。新阶段不等于新页面、新会话或新项目。
- 讨论不自动改稿；下一步建议准备可修改请求，不自动发送。
- 研究、策略及引用彼此区分；原资料不被策略反向改写。
- 局部选择、候选比较、明确采用、查看旧版不改变当前采用、选择性接续继续保留。
- 目标、方法、品牌与项目不做强制设置向导。当前没有 KPI 的例子仍然有效，不补造数字。

灰阶、合成资料和有限执行是原型边界，不作为本轮缺陷。跨 HTML 的临时状态重置、未接模型、未实现导出也已经明确披露，不包装成新发现或本轮已解决的能力。

## 4. 收敛成一个工作区，而不是六步向导

六状态保留作为演示脚本，不进入正式导航。统一头部建议：成果名称、当前版本、工作/阅读切换、版本入口；资料与依据放在一处可展开摘要。

| 用户正在做什么 | 右侧呈现 | 主要动作 |
| --- | --- | --- |
| 判断资料是否适用 | 背景与判断对照 | 选一条继续问、补资料 |
| 形成或深化策略 | 当前方向与关联判断 | 深化、组合、局部修改 |
| 检查一次修订 | 原版与候选的差异 | 采用、保留、继续改 |
| 阅读与带走成果 | 同版报告 | 选中内容后接续，或查看依据 |

讨论、规划、执行仍是行动模式，不与上表一一对应。计划与方法按任务需要出现，不为了补齐设计而强制用户经过。

接续沿用本次已经画出的预览，但必要摘要不能永远只固定为“目标 + 主张”。有品牌限制或产品使用边界时，应把与所选动作有关的约束列入预览，由用户看清哪些内容会继续生效；不复制全量 Brand Kit，也不静默丢掉关键限制。

## 5. 视觉方向建议

建议采用“安静的专业工作区 + 有编辑感的成果”，而不是仪表盘或管理后台。这里是下一版设计方向，不是已定稿的品牌规范。

- 软件界面：浅暖灰背景、白色工作面、深墨色正文，少量低饱和紫色用于主动作与选中状态。不加大面积渐变或装饰光效。
- 成果内容：较清晰的标题层级、足够大的中文正文、简洁来源标识。策略用关系与取舍图；分析用实际数据表或图；创意用适合内容的表现方式，不强制所有成果使用同一种三卡片模板。
- 导航与工具：统一线性图标和按钮尺寸，边框少于当前线框。层级主要由版式承担。
- 客户品牌：影响成果的表达与模板，不替换 Mokina 的全局产品身份。
- 状态：选中、正在处理、需要回应、候选、当前使用用文字和视觉共同表达。模拟状态保持清楚，但不重复塞进业务正文。

下一稿先用“深化工作面”和“同版报告”验证同一套视觉；局部比较作为工作面内的状态覆盖。不要先做完整组件库或给六张图分别套六种风格。

## 6. 下一轮执行顺序

1. 在现有深化工作面上压缩头部和说明，统一成果工具栏、对象选择与动作提示。
2. 在同一页面的背景与衡量区域补品牌约束、方法解释、有 KPI 的输入变体；无 KPI 的入口继续保留。
3. 用同一套视觉落工作、比较、阅读及专注阅读状态，原灰阶线框保留对照。
4. 浏览器检查 1440×900、1280×800 下的选中、编辑、比较、阅读、返回和草稿。不要用模型测试替代页面检查。

这一轮到高保真交互稿即可，不因此授权模型接入、后端、重选底座、生产代码重构或发布。
