# M1：业务事实与 Brief

基线：`c757101fc70a5465df4e795e3434755c4bd166a1`，依赖 PR #16；本轮不合并、不替换现用应用。

## 本轮完成条件

- 业务背景区分待确认建议、已确认事实与个人偏好；确认必须是用户动作，不从聊天或“请预览”推断。
- 任务 Brief 包含目标、受众、交付项、KPI 口径、预算、周期、限制和缺项。未知输入保持未知，不能把估算标成事实。
- 明确选择背景版本与条目后复用；旧 Brief 持有完整来源快照，背景修改不改变旧任务。
- 背景与 Brief 是同一 HTML 成果及版本机制中的文档；受控编辑不覆盖不认识或已被外部修改的 HTML。
- 保存与开始制作分开；执行范围只来自明确选择的交付项，并通过既有发送与运行路径交接。
- 项目／会话切换、刷新、读取失败、保存冲突及结果未知不丢草稿、不串状态、不自动重复执行。

## 营销评审验收

Q01：输入“禁止线下活动”，Brief 与执行交接完整保留该约束；不得靠改名规避。Q05：建议促销不能因用户要求预览变成已确认业务事实。预算、人员、产能、供应商报价和周期不足时明确列为待补充，成本测算和方向比较留在 M2。

## 验证范围

先完成事实确认、来源固定、冲突及未知结果的回归用例，再实现服务与界面。使用隔离数据验证无背景直接开始、确认背景复用、任务变更及项目／会话切换四条流程。重要界面记录 1440×900、900×600 同数据前后证据。完成 guard、类型检查、相关测试与构建、缺陷优先审查及最终提交 CI。普通功能改动使用源码运行环境，不重复打包。
