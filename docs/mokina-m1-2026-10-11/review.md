# 缺陷优先审查与资源清理

| 问题与影响 | 处理与验证 |
|---|---|
| 相同 operationId、不同正文的回执可能替换本地草稿 | 先记录失败用例，再要求编号、正文、正式版本均匹配才确认成功；组件回归通过 |
| 已保存 Brief 的来源被移除后无法核对保存结果 | 目标锁内先核对已提交请求，再为新请求读取来源；回归验证删除来源后仍能确认原结果 |
| 长表单中的状态反馈、标签可达性不足 | 状态放到滚动区外，字段显式 aria-label；1440/900 浏览器流程通过 |
| 文件保存与版本保存之间失败 | 原 operationId 补完版本；未知结果刷新后只读核对，不自动 POST；API、组件、浏览器覆盖 |
| 并发首次保存、历史请求覆盖、读取失败 | 既有锁和版本 revision 防冲突；历史操作不能覆盖当前；读取错误不会成为空数据；后端回归通过 |
| 项目根目录缺失 | 核对宿主懒创建契约：托管新项目可尚无目录，首次保存负责创建；外部导入目录缺失必须报错。CI 暴露错误假设后补充两类回归，未将合法新项目当成读取故障 |

不引入第二套持久化正文或运行引擎：复用 HTML、版本锁、恢复 store 和原发送路径。代价是被外部修改的受控 HTML 必须明确处理，表单不会静默覆盖它。

已停止并移除本轮 8 个失败浏览器运行数据根；成功浏览器环境由测试生命周期清理。真实模型隔离数据与临时凭据副本已移除；截图、失败日志、输入与产物保留在本轮 output。视觉基线临时测试及源码备份已移除并核对源码恢复。本轮没有创建原生应用副本、挂载或 LaunchServices 注册；现用应用、用户数据及历史 output 未清理。
