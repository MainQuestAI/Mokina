# M3 缺陷复审与处理

第一次独立只读复审使用 claude-code 技能，实际模型 `claude-opus-5-5[1m]`，会话 `84c51f6d-f2dd-4ee5-aec3-1116b601b4ff`。原始回执保留在本地 `output/mokina-m3-2026-10-12/review.log`。审查者只获得 diff，未执行测试；其条件性判断没有被直接当作已复现问题。

| 发现 | 核验与处理 |
|---|---|
| 保存失败后无法继续编辑 | 400/404/409 明确拒绝可返回编辑并保留文字。存储失败在版本锁内、原写操作结束后读取清单确认 operationId 不存在，才返回可编辑的明确失败；读取清单失败仍为未知。网络未知或 GET 未找到不能自行清除 pending，只有显式同身份重试，防止旧请求晚到后重复创建。边界超限回归证实没有新增清单记录。 |
| 组合后字段行号错位 | 已用失败回归确认；协议拒绝同时组合与编辑，UI 分次操作，组合候选可继续编辑。预算文本标记绕过复算另补失败回归并修复。 |
| 不规范旧标记导致全部无法编辑 | 检查跳过歧义/不支持字段并返回原因；合法字段仍可编辑，保存未知字段拒绝，预算缺项不伪造默认值。支持部分旧稿，不扩展任意 HTML 编辑。 |
| 含资源成果直到保存才报错 | GET 先返回不可编辑及原因，前端锁定入口并提示章节修订；相同校验保留在 POST。 |
| 继承父版本缺失影响旧路径 | 显式 evidenceVersionIds 必须存在；隐式旧父引用恢复原有兼容行为。现存冻结字节或摘要损坏继续拒绝。 |
| 组合丢失共享证据 | sectionId 在现有协议必填，因此“无全局章节来源”假设不成立。为保护其他章节可能仍引用的基线来源，保留基线声明，加入所选供体声明；冲突 ID 和超过八来源明确拒绝。 |
| 连续输入误报草稿失败 | 连续三次中文 change 回归通过；同一次保存增加同步闸门，快速重复点击只发一次 POST。 |
| 伪造/损坏回执注释 | 忽略非权威注释解析错误；只有 manifest 的 operationId 匹配才返回回执。读取恢复仍校验完整请求。 |
| 其他 P3 | 保存按钮排除未选章节/改回原值；数值写回规范化；备份可在面板中读取/下载 JSON；可展开 HTML 核对属性变化；目录定位采用 replace 并核对当前项目；contracts/比较组件测试纳入 CI；补齐繁体中文。 |

保留的工程取舍：金额采用现有精确十进制格式（可省略末尾零）；CLI 沿本地 Mokina daemon 路径，团队鉴权扩展不属于 M3；非中英语言的新键沿项目允许的英文回退，未声称完成各语种专业翻译。人工专业签收独立待办。

先前浏览器失败均保留回执：内联编辑区过小后改共享 Dialog；首轮 portal 点击触发底层面板关闭已修复；刷新用例曾在 pending 乐观渲染但 POST 尚未发出时重载，未真正进入故障注入路径。保存中现显示加载状态；回归先确认一次 POST 且请求结束后再刷新，证明服务端已提交而客户端丢响应的恢复。失败回执不计入最终验收。

## 第二次静态复审后的收敛

同一 Claude Code runner 返回了进一步静态意见，但使用 `P2-1` 而非约定 `[P2]`，runner 的格式校验失败；此轮不记为完整的独立复审覆盖，也不宣称 NO_FINDINGS。意见经当前 Agent 核实后处理：

- 组合预算章节现在重算相关表及所有同索引汇总（包括章节外汇总）。不同预算表序号布局或供体跨章汇总明确拒绝，避免数字指向错误表；已保存来源说明也不再笼统声称所有预算已复算。失败回归 `combine-summary-red.log` 在修复后转绿。
- 允许有效页内锚点，组合后校验目标仍存在；其他资源/可执行入口维持限制。
- 升级后无法识别的旧草稿字段提供先备份、再移除入口，不因不可见条目永久阻塞合法编辑。失败回归 `stale-draft-red.log` 在修复后转绿。
- 本地 Next 自动生成的 `next-env.d.ts` 差异从交付移除；清理未使用文案，候选缺少基础版本明确拒绝。金额格式仍沿既有十进制契约。

一次有效独立审查、一次格式不完整但有用的静态补充，均与本轮实际行为测试区分记录。

最终浏览器复跑还发现验收时序缺陷：确认保存结果后，旧断言只检查列表包含 Candidate，而该字样在确认前已经存在。立即关闭编辑器可能中断回执确认。回归现改为等待候选实际选中且待确认入口消失；保留失败报告 `browser-final-race-reports`，未改生产逻辑或放宽超时。
