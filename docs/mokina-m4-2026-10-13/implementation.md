## 工作范围

- 原生恢复容量：设置→关于展示活动记录、可整理删除凭据及归档数量；显式整理释放 512 条槽位。保留删除身份、CAS、未知发送记录和草稿。容量全由原生恢复库派生。
- 归档兼容：gzip 只装删除凭据，保持 recordId/previousRecordId；先发布归档，再写旧宿主拒绝的 v3 profile 标记，最后清除重复散文件。中断可读或明确失败，不自动重发。缺失/损坏归档不能被视为空库。未整理的旧 profile 保持 v2。
- 终端能力：`tools-pack recovery-maintain --base-root <absolute> --namespace <supported> --json`，离线检查；整理还需 `--compact --confirm`。这是 Electron profile 维护，沿已有 profile-migrate 所有权，不让 daemon 推测 Electron userData。
- 日常交付：沿已有指定版本 HTML/ZIP/PDF 与恢复包链路检查成功、资源缺失和版本身份；不建立新正文仓库。明确 macOS arm64、本地个人、Codex、HTML/ZIP/PDF 的验收范围。
- 同包验收：最终提交构建临时候选，隔离干净安装、旧 profile 副本升级、重启、草稿、真实模型及导出。包、SHA、摘要与最终 CI 对齐后提交可审查 PR。

## 故障与版本兼容策略

- 整理、读取及写入共用 profile 级 SQLite 交易锁；另一程序操作中明确返回 `recovery-store-busy`，不接受后再丢弃。进程退出或被终止会释锁。锁文件不作为迁移数据复制。
- 已整理 profile 可在完全退出应用后执行 `recovery-maintain --expand --confirm`，先展开所有删除凭据，再降回 v2 标记；过程中保留活动记录。展开后可能重新达到容量上限，这是旧宿主限制，不删除凭据规避。
- 不提供自动压缩，不删除活动草稿、不重发未知请求、不压缩作品或版本。归档解压上限 32 MiB，完整性错误直接阻断；旧 v2 未整理数据格式不变。
