## 2. 两项缺陷关闭

### P1 / F03 / T07

原“正文→表格→正文”重复 heading/group 与重置part序号，前后正文同key。实际面板修复前4失败/1通过：单选扩大为两段，两段一起点击则取消选择。同命令重放仍失败。修复以首个稳定fragmentId、资料名、源摘要与解析版本联合标识选区；旧无fragment的展示用确定源序号，不认领歧义旧key。

改后5项回归通过，覆盖前段、后段、两段、多表格、重复标题、长段分片及重读重确认。真实parser→请求→daemon冻结→磁盘前/后探针通过。local.11 Electron实际勾选，POST分别只含fragment:1、fragment:3或二者；回执与磁盘正文仅有before table、after table或二者，未选table row不存在。三种绑定同会话持久化，原生确认Web Locks可用。

### P2 / F04 / T11

修复前新增9项回归中7项失败：no-op/身份拒绝/条件消费擦掉B，旧read-back与hydration写回A，独立renderer队列未协调，桌面缺锁仍宣称保存成功。受控promise重放确认，不靠sleep。

修复让读取、CAS、消费和发布进入同源Web Locks及按键队列；保留持久CAS。发布前核对调用开始捕获的缓存，旧IPC值不能覆盖已发布B。no-op/拒绝读最新权威值后仍须通过发布条件；hydration加入同一锁，并发更新显式报错并保留数据。缺可靠锁返回失败，不宣称原子保存。

改后9项通过：权威B、缓存B与下次发送B一致；覆盖迟到initial/read-back、独立renderer模块队列、缺锁、缓存失败重开及hydration冲突。强化错误断言后两缺陷14项再次通过。local.11原生断点9/10保留原requestId，一个逻辑run；只查询或清理，不重发。同profile双原生业务窗口仍是宿主缺口，模块并发/CAS不替代其验收。
