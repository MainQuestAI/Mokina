结论：**终局工作链的工程实现已齐，缺口集中在「证明」而不是「建造」**——专业质量证明（G11）、真实连接证明（G04 边界）、以及让以上证明能在含 M5 的应用上发生。因此 M6 定为**验收收口**。

另一个硬依赖：M2 起已有两份具体成果完成工程复算（Q01–Q05，见 [M2 验收](../mokina-m2-2026-10-11/acceptance.md)），明确「人工专业结论待审阅、不能由 AI 自评代替」；这些积压样本是 M6 专业评审的直接输入。

## 2. M6：验收收口（建议下一批）

目标一句话：把「测试通过」变成「用户与专业签收」，让含 M5 的完整工作链在真实应用、真实连接、真实专家评审下闭环。

### R14 · M5 基线候选包与同包隔离验收（先行依赖）

- **任务**：从基线构建 0.0.5-local.1 候选（macOS arm64，Node 24.15.0 正式验证环境）；按 M4 同包门禁跑隔离验收：干净安装、旧 profile 副本升级、重启恢复、窗口/键盘与中文输入、真实模型一次完整任务（覆盖 M5 网页证据链）、指定版本导出；包、SHA、摘要与最终 CI 对齐。
- **PR 切片**：打包与验证为运行性工作（output 留证），仅在发现缺陷时产生修复 PR；不为基础流程改产品代码。
- **退出门槛**：同包关键链全绿；缺陷为零或已修复复验；候选保留在固定应用目录，**替换现用 0.0.4-local.1 须用户另行授权**。

### R15 · Codex 首次连接与诊断一致性（G04 边界）

- **任务**：真实配置下完成首次连接；设置、登录、诊断和运行共用身份解析在自定义 CLI/HOME、PATH 缺失、认证过期三类情形下分别正确；连接结论写入验收记录。
- **PR 切片**：以真实验证为主；诊断矛盾（如 PATH 双源）若复现则小修复 PR（先红后绿）。
- **退出门槛**：首连成功且三类故障情形行为正确；诊断结论与实际执行一致；无伪造成功。

### R16 · 专业评估集与人工签收（G11，M6 主线）

- **任务**：
  1. 固化评估集：登记评审样本——M2 积压的两份成果、M3 方向组合/接续样例、M5 网页证据成果（真实公开来源读取→选择→冻结→引用定位全链）、至少一份含预算/禁投约束的任务；沿用 [quality-rubric](../specs/Mokina-v0.0.2-Local-Preview-Spec-2026-10-04/fixtures/quality-rubric.json) 记录，评审在 R14 候选包上执行。
  2. 五维人工评审（约束遵守/判断取舍/事实来源/行动可执行/成果可读），每项记具体章节与理由；编造来源、违反禁投、预算超限/不守恒、估算说成已实现为硬失败。
  3. 缺陷登记→修复 PR（先红后绿）→定向复验；修复只复跑受影响范围。
- **退出门槛**：全部样本有人工评语；硬失败为零或修复后复验通过；签收结论或「带缺陷清单的明确边界」成文。**工程报告不替代专业结论。**

### R17 · 小项收口（并行）

- i18n：17 语言补 M5 新键人工翻译（现英语 fallback）；`i18n:check` + 键集完整性测试。
- CI 余量（M5 P3-4）：validate 接近超时的批次拆分或超时调整；以两次 main CI 实测时长为依据。
- 可选并行 R17b：性能容量基线（路线图 §8 未测项）——逐步增长的合成项目测列表/切换/保存/导出时间与内存，记录当前基线与可支持容量。

## 4. 常设规则（沿用，不因批次改变）

- 每批：`pnpm guard`、全仓 typecheck、涉及文案的 i18n、相关构建与行为回归；新缺陷先红后绿；最终独立缺陷审查；CI 绑定最终 SHA。
- PR 保持 Draft；**合并、发布、替换现用应用、打 tag 须用户逐次明确确认**。
- 原生相关验证用临时应用与隔离数据；每轮测试后按 [AGENTS.md](../../AGENTS.md) 清理；现用应用与用户数据不动。
- 人工专业结论与自动检查分开；测试通过不等于用户签收。
- 不承诺日历日期，按完成门槛推进。

## 5. 风险与不确定项

- **R16 依赖真人专家时间**：计划假设评审人可投入；若不可得，M6 降级为「评估集固化 + 工程预审 + 等待签收」，先推进 R17 与 M7 候选中不依赖签收的部分。
- **真实模型任务的波动性**：M2 曾出现长 run 被取消的先例；验收脚本错误不影响成果时保留原状态、不回写成功（既有惯例）。
- **CI 余量**：validate 批次继续膨胀会先于功能成为阻塞；R17 不做则至少每次合入后记录余量。
- **候选包升级路径**：0.0.4-local.1 → 0.0.5-local.1 的 profile 迁移依赖 M4 的 R12/R13 机制；隔离副本先行，失败可回退。
