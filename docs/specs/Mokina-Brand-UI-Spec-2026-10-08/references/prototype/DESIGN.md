# Mokina V0.0.2 前端详细设计

> 阅读顺序：本文件保留历次设计与验收记录。相同范围的说明以文末最新日期段落为准；历史验收不自动适用于后续修改。当前全页状态见文末「2026-10-04：全页 Liquid Glass 精修」。

## 定位与打开方式

从本目录打开 `index.html`；`material-compare.html` 是独立的材质对照入口。页面只依赖项目内的 `styles.css`、`glass.css`、`stage-two.css`、`glass-material.js`、`app.js` 和本地资源，无需远端字体或网络。所有项目、草稿、版本选择和协作栏宽度保存在浏览器 `localStorage`；左下角“演示状态”可恢复初始样例。

这是独立设计项目中的可交互前端原型。示例场景为“国庆新品试饮”；30 万元预算是虚构样例。模型生成、真实资料解析、持久化服务、工具日志、客户接口和正式 PDF 导出均未接入。HTML 导出会下载一份包含指定示例版本内容的独立文件。

## 视觉系统

唯一参考为需求指定的工作区 v4 图片，色彩来源、OKLch Token 与观察规则见 `brand-spec.md`。页面采用有明暗变化的中性环境、实底正文和浮于内容之上的玻璃导航／操作层。青色仅作为主动作和少量状态标记；选中行使用中性薄填充。背景和工具条保持单一连续层，内部按钮不再叠加玻璃。字号为标题约 30px、正文 16px／1.65、辅助文字 13px 起、工具条约 14px。

### 第一阶段：工作区材质稳定性（用户已确认强度）

第一阶段把材质参数接入方案工作区的侧栏、成果工具条，以及现有首页“更多”菜单。用户已确认材质强度；第二阶段移除了“继续制作”的误导性下拉箭头，仍为直接跳页。对照页样本菜单不是产品菜单。

`glass.css` 与 `glass-material.js` 共同实现四层：中性透明背景透射、仅限曲边的实时背景位移、随指针轻微变化的高光和阴影、完全不参与滤镜的文字图标前景。位移输入是玻璃后方当时的页面像素，并非固定截图。尺寸变化时测量真实宽高及圆角，用 Canvas 生成带符号距离场的位移图、用 SVG 圆角环生成 alpha mask；二者按几何参数缓存，ResizeObserver 防抖更新，不在每帧重建。现有固定 PNG 遮罩仍留在基线供比较，新工作区使用尺寸适配场。三种组件变体只改变边带、位移尺度及中心模糊强度，参数见 `MATERIAL-PARAMS.md`。

工作窗口保持克制灰阶环境；正文和协作内容保持实底。成果工具条浮于真实滚动容器，正文和分隔线滚到其下方时参与背景取样。单个指针事件至多排入一个 RAF；离开、卸载、重绘或减少动态偏好变化时取消回调并复位高光。减少动态效果停用位移及响应，减少透明度切为实底。SVG 背景滤镜不支持时保持清晰可读的普通玻璃回退；“支持声明”只说明走哪条代码路径，并非实际像素证明。

`material-compare.html` 保持同背景和同步滚动，左侧是本轮冻结基线，右侧是尺寸适配材质，可在不变换滚动位置的情况下开关折射。白底、密集内容和本地合成深浅图用于检验透射和边缘。测试图是验证夹具，绝非客户素材。当前完整基线及 SHA256 清单在 `archive/stability-baseline-20260926/`。旧 `archive/*-before-material-v2.*` 与 `shots/material-before-1440.png` 只属于更早一轮，不代表这次修改前状态。

本次独立 Chrome 的指定内容视口、实际交互、短时性能轨迹与未通过项见 `ACCEPTANCE.md` 和 `evidence/`。OpenDesign 内置预览、系统偏好运行中切换、浏览器缩放和短录屏未完成，明确保留为验收缺口。用户已确认白底正文下的材质强度；本轮没有据此推广到其他工作区。Safari、Firefox 的合成输出未验证。此方案是 Web 材质近似，不调用 Apple 原生 Liquid Glass API。

分层原则参考 Apple 官方 [Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/) 与 [Get to know the new design system](https://developer.apple.com/videos/play/wwdc2025/356/)：操作层浮于内容之上，避免在内容和工具条内部连续套玻璃。这里采用独立 Web 技术路径，不复刻或声称具备原生光学实现。

## 第二阶段：工作区交互与版本闭环

本阶段在材质强度获确认后进行，仅修改本独立原型。修订页复用导航、固定来源、协作消息、输入草稿和可调列宽；基础章节与候选章节在右侧成果区并排。全宽阅读必须主动开启，状态与列宽都记在本地，可单击恢复协作区。`stage-two.css` 只补充修订布局、文档层级和状态提示，仍沿用当前颜色、字体与玻璃参数。

修订开始时固定基础版本及章节。前端模拟保存会复制该版本的完整文档，只替换选中章节正文，其他章节、表格和标题仍来自固定基础版本；完整候选弹窗可逐段核对。候选保存后在成果阅读区留下待处理入口，重开仍可找到。采用前正式稿不变；采用时写入新版本快照并保留旧版供阅读，旧任务不能覆盖更新后的正式稿。此处“生成”只演示状态与版本语义，绝非模型已生成合格营销内容。

成果正文把营销结论放在标题下方，版本身份合并为一行，协作区过长的来源名称可截断且保留完整按钮名称。继续制作直接打开来源确认页，不显示下拉箭头；指定历史版本的章节摘录在创建关联项目时冻结，形成独立未发送草稿。任务编号移入“任务详情”；章节和版本选择使用可见选中态及 `aria-pressed`，弹窗保留键盘焦点约束。

第二阶段修改前的 `app.js`、`styles.css`、`glass.css`、`index.html` 与文档副本及 SHA256 在 `archive/stage-two-before-20260926/`。实际浏览器回归和边界见 `ACCEPTANCE.md`。没有公共 API 或后端结构改动。

## 关键状态与对象规则

- 一个项目持有自己的消息、未发送草稿、资料选择、固定草稿快照、候选任务和版本。切换项目不会改写其他项目的草稿。
- 正式版本、历史版本和未采用候选分别标明。选择历史版本后，成果阅读、继续制作与导出都沿用当前查看的版本。采用候选才创建新的正式版本。
- 资料文件按同一 `selectedFiles` 集合驱动预览与快照确认；确认时复制为 `draftSnapshot`。未选文件不进入草稿快照。32,000 字是原型中的上限，演示状态可触发超限。
- 继续制作保存来源项目 ID、固定版本、章节和当时摘录。来源项目可双向返回；部分创建失败保留目标项目与草稿，不重复创建。
- 修订任务带 operation 编号。运行中与保存中阻止覆盖启动；旧 operation 回调被忽略。替换文件缺失、候选读取错误和保存错误均保留重试入口。放弃确认只清当前 operation，正式稿不变。
- HTML 导出从同一指定版本正文构造；未冻结资源拒绝导出。PDF 显示未接入，不下载假文件。

## 演示状态

左下角“演示状态”与产品主操作分开，可选择空项目、加载、已有稿运行、失败／中断、未知、运行取消失败、修订取消失败、文件缺失、候选读取失败、候选保存失败、旧回调、采用冲突、资料加载／解析失败／部分读取／超限／原件变化、项目创建失败与快照部分失败。状态文字明确写出下一步；它们只用于前端演示。

## 可访问性与尺寸

键盘焦点可见，弹窗约束 Tab 并在关闭后返回先前控件；Esc 关闭菜单、演示状态与弹窗。运行与错误状态同时使用文字和颜色。减少动态效果由系统媒体查询和演示开关控制；减少透明度由支持该媒体查询的浏览器或演示开关控制。若系统不提供透明度偏好事件，手动开关可直接演示，不声称系统已联动。

桌面目标为 1440×900 与 1280×800。左导航约 200–214px，协作区默认 360px、可调至 316–470px，成果区占余量；窄屏时工具条换行，正文保持 16px，表格在自身容器内滚动。第一阶段的工作区材质及第二阶段修订布局，均在独立 Chrome 的两个目标内容视口检查；第二阶段流程回归结果见 `ACCEPTANCE.md`。

本文件描述前端原型行为。真实版本锁、文件快照、任务续跑、模型输出质量、正式导出及生产代码集成，需要在产品仓库中另行实现并验收。活动页示例未使用虚构产品图；指定素材尚未提供，页面以文字主张和版式演示成果结构。

## 2026-09-28：Mokina 设计体系 v0.1

当前设计体系入口为 `mokina-design-system.html`，不是原型全流程验收结论。以当前源文件为基线；用户附件作为问题证据，工作区 v4 作为方向参考，均实际查看。没有回退归档页面。修改前源文件与 SHA256 位于 `archive/design-system-before-20260928/manifest.json`。

统一体系覆盖空间、材质、排版、图标、组件状态、产品语言及验收。颜色沿用 `brand-spec.md` 的六个 OKLch 变量，系统字体沿用现有栈；新增材质参数是本项目建议值，不是 Apple 官方测量值。原则来源：https://developer.apple.com/videos/play/wwdc2025/219/ 。

### 实际接入

- `design-system/mokina-system.css` 是集中维护的新规则入口，在原样式后加载。布局规则仅作用于 `.material-stage-one`（方案工作区、章节修订），不触碰版本/草稿状态逻辑。
- 侧栏与成果控制采用统一外边距、16px 圆角（`--mk-radius` 实测值）、细边缘和轻阴影，消除侧栏专用深色环境条带与厚重侧向阴影。移除该工作区的仿窗口彩色圆点。
- 中栏内容仍为实底；助手消息移除重复底卡，用户消息保留轻填充。输入容器绝对定位于协作区底部，消息滚动区预留空间。输入框现已复用工具条的四层材质及几何位移场；可感知光学一致性仍待动态复验。
- `design-system/mokina-icons.js` 集中 15 类自绘功能 SVG；所有页面通过原 `icon()` 接口读取。统一 24×24 网格、20px 控件图标、1.65 笔画与圆端。不是 SF Symbols，不涉及品牌图形替代。
- `:root` token 实测值（与设计稿参数一致，非官方光学数值）：`--mk-radius:16px`、`--mk-control-radius:8px`、`--mk-target:44px`、`--mk-icon-stroke:1.65`、`--mk-duration:160ms`；面层 `--mk-control-fill` 0.58 alpha、`--mk-control-blur:7px`，导航 `--mk-glass-fill` 0.32 alpha。`--mk-duration` 统一驱动玻璃边缘高光与“更多”菜单等过渡。
- `mokina-design-system.html` 提供规范、实际原型嵌入、隔离组件状态演示、键盘菜单与语言映射。嵌入原型会共享原型本地状态；组件演示不修改业务状态。

### 未完成的体系迁移

首页、项目列表、资料、版本、继续制作和活动页没有整体迁移；图标已共享。输入框与导航/工具条的完整光学一致性仍须检验。共享四层结构接入不等于已通过真实浏览器光学验收。新的布局需要重新进行双内容视口与实际滚动验收，旧测试不能证明新布局通过。


### 2026-09-28：输入区与工具条材质统一

方案工作区和修订页的协作输入容器使用 `glass-plane` / `data-glass="toolbar"`，保留侧栏、工具条、菜单三种变体，不新增第四种。输入容器与成果工具条共享 `--mk-control-fill`（0.58 alpha）和 `--mk-control-blur`（7px）；导航仍用较轻环境透射。外容器不使用 backdrop-filter，避免提前截断内部边缘层背景取样；面层模糊、边缘位移和清晰前景分别绘制。

输入框真实尺寸驱动 9px 边带、3.8px 最大位移与同心遮罩；拉高输入框或调整协作列宽会更新几何资源。ResizeObserver 的防抖队列改为 Set，保留防抖期间所有变化组件。指针高光、运行中偏好切换和卸载沿用共用清理逻辑；减少透明度后容器实底且两层滤镜关闭。文字、标签和发送按钮均不参与位移，不在按钮内部重复叠玻璃。

滚动区由输入容器高度同步底部留白及 scroll-padding，最后一条消息可滚至输入区上方。原型状态、草稿保存与发送逻辑未改。此轮仅在原有方案工作区范围接入；其他项目协作区不增加材质结构。

本轮测试与静态证据见 ACCEPTANCE.md。尚未取得动态折射、真实滚动和双视口交互证明，不宣称原生 Liquid Glass 或最终验收通过。


## 2026-10-03：Liquid Glass 工作区重设计与验证边界

### Overview

本轮沿用 `index.html` 入口，加载 `design-system/liquid-workspace.css?v=20261003`，覆盖方案工作区及章节修订页。保留业务对象、版本与候选状态、草稿及既有 `localStorage` 数据；首页、项目列表等页面未整体重设计。重设计前副本位于 `archive/liquid-glass-redesign-20261002/`。

视觉依据更新为已指定的 Liquid Glass 设计体系；历史工作区 v4 图片保留作先前方向记录。整体采用中性灰白环境、实底正文和轻盈功能层，蓝色仅作少量操作强调。实际颜色与组件参数以本轮覆盖样式为准，属于项目 Web 派生值，不是 Apple 原生光学参数。

### Typography

标题与正文统一使用 `SF Pro SC, system-ui, -apple-system, "Segoe UI", "Helvetica Neue", Arial, sans-serif`；未打包专有字体，实际字形取决于系统回退。成果标题采用自适应字号，正文保持清晰层级与宽松行距。

### Layout

桌面维持导航、协作区、成果区三部分；正文与消息使用实底，成果工具条移入成果滚动容器并采用 sticky 定位。此次补入容器宽度约束和移动菜单定位修复；全宽阅读的网格规则提高优先级，避免被普通工作区列定义覆盖。窄屏改为上下组织，保留成果和协作内容。

### Elevation & Depth

侧栏、关键工具条与输入区复用现有背景透射、曲边位移及指针高光实现，前景文字和图标保持清晰。已有减少透明度、增强对比和减少动态处理继续保留。代码存在这些处理，不代表本轮已完成对应真实浏览器效果验收。

### Components

工作区菜单使用 absolute 定位并锚定触发控件；按 Escape 关闭后，焦点返回触发控件。成果工具条内主次动作与阅读标签保持分组。菜单、滚动工具条和全宽阅读需连同最新尺寸规则一起验收。
