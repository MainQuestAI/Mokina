# 03｜独立桌面与本地运行

## 3.1 技术路线与责任

继续使用现有 Electron desktop + packaged + sidecar + Next standalone/daemon。`tools-dev` 只负责开发；`tools-pack` 负责打包、安装和桌面 smoke。禁止第二 Electron 外壳、第二 launcher、用临时 shell 脚本替代宿主生命周期、依赖用户 `pnpm dev`。[S03/S14]

T01 首先打一个真正的 Mokina 桌面纵向切片：Finder 启动 → 原生首页 → 读取一个合成项目 → 退出 → 重开。这个切片放在 B2/B3 之前，不能把桌面未知项全部推到最后。

## 3.2 产品身份（本包新增设计）

配置来源建议为 `tools/pack/resources/mokina-product.json`，由 tools-pack 编译进既有 packaged 配置，向 daemon/desktop/web 下发只读身份。共享 DTO 放 contracts，不允许运行时从 tools 源码 import 业务逻辑。

| 字段 | 本版本值/规则 |
|---|---|
| productId | `mokina` |
| productName | `Mokina` |
| productVersion | `0.0.2-local.1`；由构建显式传入，和上游 engineVersion 分开显示 |
| bundleIdentifier | `ai.mainquest.mokina.preview`；本地预览后续小版本保持稳定 |
| releaseKind | `local-preview` |
| package namespace | `mokina-local`；QA 使用隔离 namespace + 显式隔离 OD_DATA_DIR |
| default edition | web 构建与 daemon 均 Mokina on；不允许两端互相矛盾 |
| updater | 本版关闭自动检查、下载、安装和上游 fallback；设置中说明手动替换应用 |
| upstream cloud | 本地核心流程不要求 OpenDesign/AMR/团队账号；无配置的团队入口不发无意义请求 |
| telemetry/news | 未明确启用时不发送遥测，不请求上游 whats-new；沿用现有可配置能力边界 |
| custom URL scheme | 本版不注册/接管 `od://`；不新增必须依赖 OS scheme 的流程，应用内导航照常 |
| internal packages | 保留 `@open-design/*`、内部 od CLI/协议常量；不批量 rename |

Mokina profile 必须计入相关 build cache determinant。不能从 off 的旧产物拿到 on 包，也不能用相同构建仅换环境变量冒充两个 edition。[S14]

应用图标优先从已有 Mokina 资产提取并按现有打包工具制作；无可用图标则本版采用已有文字标识的简单应用资源，不为此启动新品牌设计项目。第三方 LICENSE/NOTICE 不随产品更名删除。

## 3.3 包内依赖与清洁环境

产品包必须包含生产 web、daemon、必要的 Node/runtime、前端静态资源、已选场景/Skill、导出所需资源，以及文本 PDF 解析依赖。开发机器路径、node_modules 外链、临时目录、用户 auth.json、`.env` 和客户资料不得进入包。

首版沿用 `pdftotext` 文本提取实现，默认路线是把目标平台可执行文件及依赖/许可证作为受控资源打包，daemon 使用明确资源路径调用，开发模式仍可按既有 PATH 探测。T05 验证它在无 Homebrew PATH 下可运行。若分发依赖无法满足，改用仓库已存在的包内解析器需要同一测试集通过，并记录等价替换；**不能静默把 PDF 功能降为安装后不可用**。本版不做 OCR。[S06]

Codex CLI/账号作为一次性外部依赖保留，但 Finder 子进程必须能解析实际 CLI 和所需执行环境，不能仅在交互 shell 中可用。现有 adapter 负责选用路径；诊断可允许用户选择已有 CLI 的绝对路径，不自动下载/安装、不执行拼接的用户 shell 命令。

## 3.4 Codex 首次连接

设置页复用现有 Agent 配置，增加或复用“检查连接”结果区。检查顺序：CLI 可定位及版本 → 现有认证状态探测 → 配置/model 可读 → 用户点击真实测试后验证模型执行。前三步不发送真实营销任务。

认证成功不能通过 `~/.codex/auth.json` 是否存在单独判断：官方支持文件和系统凭据存储。必须尊重已有 CODEX_HOME/登录状态，不覆盖全局配置，不在备份、日志或 UI 中显示令牌。[E01]

缺项状态：`cli_missing`、`login_required`、`permission_denied`、`quota_or_billing`、`network_unavailable`、`model_unavailable`、`unknown`。沿用 daemon 既有错误分类，不另起另一套统计 taxonomy。设置页给出重试、去原生登录说明、选择现有 CLI 或复制脱敏诊断。不能因某个检测无法确认而展示“已连接”。

默认验收通道 Codex；模型使用用户现有选择和 adapter 实际可用配置，不硬编码一个可能变化的模型名。其他已支持 Agent 保留，但没有真实验收的不得标成本版保证支持。

## 3.5 数据根和稳定恢复

daemon 数据仍只认启动时 `OD_DATA_DIR → RUNTIME_DATA_DIR`。包内 resolver 先计算 Mokina profile 与 namespace 对应的数据根，再传入 daemon；此规则写进根 AGENTS 的唯一数据契约后统一消费。不得以端口、cwd 或用户目录示例另造默认数据根。[S03]

Mokina、OpenDesign、QA 的进程注册、Electron userData/session、数据与更新缓存必须相互隔离。用户主动导入的外部项目目录保持原宿主授权例外，不因为新版规则被搬走。旧开发数据不能自动扫描后吞并；仅用户选择恢复包/导入入口时进入产品。

**端口变化不是换一份草稿。** Electron profile 固定仍不足以保证不同 Web origin 的 localStorage 相同。T03 必须核对宿主现有持久存储能力：

1. 优先复用原 host 的产品级持久 KV；仅为 Composer 草稿/extras、PR3 发送意图、修订/接续 journal 增加异步存储 facade。
2. 若没有可复用能力，在 desktop main 中新增窄 IPC `mokina:recovery-store:get|put|delete`，仅允许受信任 app renderer、固定命名空间和有界 JSON 值，落在既有桌面 profile 数据所有者下；不新增数据库服务。
3. put/delete 以预期记录身份作比较，main 单写者串行处理；写成功才允许发送。Web 开发模式继续用 localStorage adapter，不能丢掉 PR3 故障语义。
4. 只迁移当前 renderer 可读的旧记录，保留原身份并防止覆盖较新草稿；不得读取浏览器其他 profile 或自动导入旧测试数据。

界面状态未恢复前不自动发送。一次有效恢复只核对原请求；不同 origin、重启、端口被占用、更新应用后均须重新验证这个契约。

## 3.6 生命周期与可用性

启动、发现、重启和停止复用 sidecar 原语；单实例锁由现有宿主扩展到 Mokina profile。重复打开应用聚焦已有窗口，不启动另一组写相同数据的 daemon。

关闭窗口与退出应用遵守现有 macOS 语义，并给出可理解状态；选择退出时先保存输入，必要时确认正在运行任务。不能通过 `pkill node`、固定端口杀进程或扫描所有 Codex 进程实现停止。只管理当前实例拥有的 sidecar；本版不承诺退出后继续后台完成任务。

异常终止后，启动读取原 run 终态/未完成状态并提示恢复；不伪造“正在继续”、不自动新建收费任务。端口冲突使用既有发现/重选机制，不能连接到其他产品的数据。无网络、无 CLI 或认证过期不妨碍本地浏览/人工编辑/已有版本导出。

## 3.7 安全和支持平台

保留生成 HTML 的隔离 origin、sandbox、CSP、禁用 Node 权限及经过验证的 IPC sender；不为兼容预览或 PDF 导出关闭这些防线。[S07/E02]

目标平台是用户实际 Mac；T00 在本机读取 `uname -m`、macOS 版本、现有 Codex/Node 版本并记录。只交付该架构的真实验收产物；另一架构、Windows/Linux 和公开公证分发不构成本轮硬门槛。没有 Apple 发布凭据不妨碍开展本地构建，但必须实际验证生成包能从 Finder 启动；不得用 Web smoke 代替，亦不得要求用户关闭系统安全保护。[E03]
