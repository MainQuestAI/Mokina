# 04｜资料与运行上下文（B2）

## 4.1 本轮只新增一个核心业务值对象

新增 **MokinaContextSnapshot**：某次任务准备时，用户选定资料摘录、品牌约束、素材和补充信息的不可变集合。不是知识库，不做向量索引、文档同步、全项目自动召回或永久用户画像。它附属于现有项目，被现有 run 引用。

继续使用 `ProjectMaterialExtraction` 的 `read | partial | unreadable`。界面阶段另行投影，不替换旧枚举。源文件 `contentDigest` 与分组定位均保留；分组 ID 只在相同提取摘要内稳定。[S06/S07]

## 4.2 输入能力矩阵

| 输入 | 本版处理 | 必须告知的限制 |
|---|---|---|
| TXT/MD | UTF-8 文本、行号/章节定位 | 编码错误不能乱码后冒充读取成功 |
| CSV | 保留原字段与行定位；数据计算使用可靠 CSV 解析器 | 文本抽取不等于已经计算，不能把缺失值变零 |
| 文本 PDF | 按页提取文本层 | 扫描页/图片/复杂图表未识别；无文本页标 partial/unreadable |
| DOCX | 既有正文、基本表格 | 页眉页脚、批注、图片和复杂排版不作事实读取 |
| XLSX | 工作表/单元格、已有公式缓存 | 不重算公式；无缓存不作零；日期序列不猜时区 |
| PPTX | 幻灯片文本块 | 图片、图表、备注不作已读取事实 |
| PNG/JPEG 等素材 | 既有媒体预览，用户明确选取为视觉资产，冻结字节 | 保存图片不等于已做视觉理解；实际多模态提供情况独立显示 |
| 品牌规范 | 复用原设计系统或选定规范文件，冻结本次采用的内容与资源 | 不是另一个 Brand Hub；不自动把整个品牌库送给模型 |
| 用户补充 | 带来源类别 `user-note` 的文本 | 是用户陈述，不冒称外部已验证事实 |

继承限制：单个解析原件 10MiB；Office 解压单项 5MiB、累计 50MiB；解析总文本 150,000 字符、长片段 8,000 字符拆分。不要为对齐 UI 改松安全上限。[S06]

本轮新增选择预算：一份快照的**摘录文本总量 24,000 UTF-16 code units（以 JavaScript string.length 为准）**，最多 20 个条目，冻结二进制素材累计 30MiB。此为可集中配置的产品选择预算，与旧 revision/continuation 的 24,000 字符检查口径对齐；UI 和后端共享同一常量及计数方式。不能静默截断、自动丢掉选项或把 token 估算当精确值。

## 4.3 选择—冻结—发送

1. 用户上传/选择原件，复用既有文件入口。读取端返回提取结果；所有局限可展开。选择小段落/页/单元格组，不按后缀默认全量纳入。
2. 前端保存“选择意图”：资源引用、预览时 digest、定位和选定组。尚不显示“本次已使用”。
3. 用户发送或确认接续时，daemon 检查所有来源权限、路径和预期 digest，在受保护项目元数据存储中原子保存快照；需要的资产复制为冻结字节，不能保留可漂移的原路径链接。
4. 受理 `POST /api/runs` 时读取已保存快照并绑定到同一 clientRequestId/run。adapter 真正获得组合后的输入时，写入最小 delivery 回执；先受理但排队中的 run 不显示“模型已收到”。
5. 成果按 sourceId 标引用；依据面板能对照快照摘录和局限。模型提到未知 sourceId 时提示来源未匹配，不替其编造证据。

资料预览以后、冻结以前发生变化，返回 `MOKINA_SOURCE_CHANGED`，不提交模型；其他草稿不丢失。冻结以后原件变化不影响该快照，也不要求 unknown 请求换 snapshotId 重发。新增尝试可以选择同一快照或显式创建新快照，但必须是新的请求身份。

## 4.4 快照内容和来源定位

每个条目有 `itemId`、`kind`、`sourceRef`、`displayName`、`sourceDigest`、`selection`、`limitations`。文本条目存所选原文 `text` 与 `textDigest`；资产条目存不可变 blob 引用、mime、byteLength 与摘要。sourceRef 只保留必要的 projectId/相对文件名/versionId 或设计系统身份，不存绝对路径、bearer URL 或凭据。

HTML 章节 sourceRef 必须指定 versionId；不以 current、latest、文件 mtime 作为冻结身份。来自当前版和历史版均按实际选定版本处理。候选来源允许显式选用，但在界面和下游记录保留“来源为候选”的事实，不能提升为已采用策略。

本版单次快照只支持已获权限的本地项目资源、现有设计系统和用户文本。网页检索仍由现有 Agent/工具按其实际能力执行并在成果引用，不新增 URL 抓取服务；未实际访问网页不能成为已读取来源。

## 4.5 冲突与预算

优先使用用户本轮明确目标、约束和指定版本；资料之间有冲突时显示冲突并在结果中保留口径。用户提供新的预算可作为“用户更新”，但不能抹去旧来源的数值。品牌风格约束可按用户明确要求修改；产品参数等事实变化须标出新依据或待核实，不静默选择一个看似方便的值。

可选条目读取失败时允许用户显式移除或“保留原件但不作为依据”后继续；不能为了一个无关附件阻断纯文本讨论。超过选择预算时展示使用量并要求缩小选择，禁止自动摘要后仍标注“原文”。需要模型摘要时，它是一项有来源、需用户确认的真实任务，不是假装免费且确定的预处理。

## 4.6 “提供了”不等于“理解了”

回执只证明编译输入中包含哪些文本/素材引用、使用哪个 parser 和 Skill、哪些未纳入。`delivery.status=submitted` 代表 adapter 已获得该输入，不证明模型逐字阅读或正确理解。结果中事实可靠性还需 sourceId 对照、数值检查与专业评审。

本版的“仅选定内容接续”是**应用主动传递上下文的契约**，不是新增跨项目强制文件沙箱。目标项目不带上游完整目录/绝对路径，不自动读取未选材料；Agent 的其他本地访问能力仍受原宿主授权与沙箱约束。必须在 trace 中验证无自动扩展来源，不能在 UI 宣称本版建立了新的硬隔离安全边界。

## 4.7 持久化与兼容

快照存放于从 RUNTIME_DATA_DIR 派生的既有受保护项目元数据区域，和 artifacts 普通文件列表分开；由 `MokinaContextStore` 按项目读写，不增加另一个数据根。正文不是公开日志，不打进 telemetry。快照不可原位修改；内容变化新建 ID。删除项目时按现有删除确认/回收策略管理，不新增定时清理系统。

旧项目没有快照时显示“此历史任务未记录可核对的上下文”，保留正常浏览/编辑/导出。不得从旧对话或文件名推算出一个“历史已使用资料”记录。
