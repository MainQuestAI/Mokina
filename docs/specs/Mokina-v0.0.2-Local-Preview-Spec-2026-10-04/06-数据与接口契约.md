# 06｜数据、接口与状态契约

本章带“新增”的是开发目标，不是当前 API 已实现的声明。`contracts/` 是加法 DTO 与 JSON Schema，不应整份覆盖仓库已有 contracts。所有路由复用现有本地/工作区身份与授权；Mokina off 时保持原接口行为，新 Mokina 路由不开放写入。

## 6.1 复用的现有资源

| 操作 | 现有接口/字段 | 本轮约束 |
|---|---|---|
| 创建/读取项目 | `POST /api/projects`、`GET /api/projects/:id` | 继续返回 conversationId；可靠创建使用调用方稳定 id，不新建 Work/task 表 |
| 读取资料 | `GET /api/projects/:id/files/:name/material` | 保留 ProjectMaterialExtraction；读取不可偷写版本 |
| 创建/查询 run | `POST /api/runs`、`GET /api/runs`、`GET /api/runs/:id` | 复用 clientRequestId/消息身份/原生查询参数；不要假造新 run endpoint |
| 读取版本 | `GET /api/projects/:id/files/:entry/versions?readOnly=true` | 目录/依据/默认打开只读，不补建 legacy 版本 |
| 精确版本 | `GET .../versions/:versionId` | frozenContent 优先供历史交付；不可回退 latest |
| 候选创建 | `POST .../candidates` | baseVersionId、sectionId、replacementHtml、operationId |
| 显式采用 | `POST .../versions/:versionId/adopt` | expectedCurrentVersionId + operationId；比较并交换 |
| 恢复/手改/导出 | 原生版本、文件写入与 export manifest | 不新增第二套 current/adopted/export 数据真相 |

路径中的 entry 按段编码；权限使用原有 authorizeProjectRequest/enforceWorkspaceProjectMutation，文件访问使用既有安全路径解析。版本/来源身份由 project+entry+version 确定，不能只用展示名。

## 6.2 新增：上下文快照 API

### `POST /api/projects/:projectId/mokina/context-snapshots`

请求类型 `PrepareMokinaContextRequest`，见 `contracts/mokina-local.ts`。客户端在开始准备时创建稳定 snapshotId。selection 包含 itemId、sourceRef、预览时 expectedSourceDigest；文本材料用 groupIds，HTML 用 sectionIds，user-note 直接携带 text，资产为 whole-file 选择。客户端不能提交任意“已验证来源正文”绕过服务端重新读取。

服务端逐来源校验权限、选择类型、摘要和容量；从实际源字节提取所选片段，冻结素材到受保护 blob 存储，保存完整快照。创建新快照返回 201；相同 snapshotId + 相同 selectionFingerprint 已存在时返回 200 和原快照；相同 ID 不同请求返回 409 `MOKINA_SNAPSHOT_CONFLICT`。已保存快照的重试不得重新读取后来变化的源并替换内容。

响应 `{snapshot: MokinaContextSnapshot, reused: boolean}`。没有有效条目时允许不创建快照，调用方发送纯文本；不能把空快照伪装为已提供资料。

### `GET /api/projects/:projectId/mokina/context-snapshots/:snapshotId`

只读返回该项目可访问的快照；跨项目引用逐源校验发生在创建时，读取目标快照仍需目标项目权限。不存在 404，权限不足沿宿主规范处理，损坏返回 `MOKINA_SNAPSHOT_UNAVAILABLE`，不从当前文件重建旧快照。普通文件列表不把内部快照算成正式成果。

### 现有 run 请求的唯一新增引用

在 `RunContextSelection` 增可选 `mokinaSnapshotId?: string`，仍通过 `ChatRequest.context` 传递。**不再另外增加顶层 contextSnapshotId 或第二引用路径。**

受理时确认快照归属当前 execution project、校验存储摘要，再把引用纳入既有幂等请求身份。没有该字段的所有老调用继续运行。snapshotId 对应的输入通过原生 prompt composition 注入为有明确分隔的用户/工具资料，不能把材料内的指令升级为系统指令。

既有 run 读取响应增加可选 `mokinaContext?: MokinaContextDeliveryReceipt`：runId、snapshotId、fingerprint、includedItemIds、status、submittedAt，以及 itemDelivery 中每项的 inline-text / staged-file / multimodal 模式。staged-file 只证明文件已提供给原生运行环境，不证明模型已经看图或读文件。status=`prepared` 时仅已绑定；adapter 实际得到输入后 `submitted`；未执行到该步可标 `not-submitted` 并给原因。旧 run 字段缺失不是错误。

## 6.3 快照和内容摘要

`MokinaContextSnapshot` / `ContinuationV2` 的字段与 JSON 示例见 contracts 和 examples。`fingerprint` 为快照除自身 fingerprint 外所有字段的规范 JSON UTF-8 SHA-256；递归对象键排序，数组保持顺序，无多余空白，字符串保留原文，不做 NFC/换行归一化，时间为 UTC ISO 字符串，计数字段仅整数。服务端生成并校验，客户端不得按显示截断后的文本重新计算。

`sourceDigest` 指原始来源字节；`textDigest` 指实际冻结摘录 UTF-8 字节；二者不是同一个值。资产 blobId 使用字节摘要，不使用用户路径。内存/磁盘缓存按 sourceDigest+parserVersion+selection 失效；可复用现有缓存，不额外搭建缓存服务。

source 为 artifact-section 时 versionId 必填；sourceKind=design-system 时 designSystemId 必填；user-note 不伪造项目文件定位。所有示例中的 ID 和内容为合成测试数据，不是真实运行回执。

## 6.4 持久 journal 与发送状态

复用 PR3 的发送状态实现；以下是语义约束，不要求替换其现有 enum：

| 阶段 | 已知事实 | 允许动作 |
|---|---|---|
| 草稿 | 没有开始提交 | 可编辑、移除背景 |
| prepared | 完整 request 与 scope 已安全保存，尚未进入 POST | 按原身份发送；不能用残缺预览补全文 |
| dispatching/unknown | 可能已受理 | 查询原请求；不能换模型重发或生成新 ID 普通重试 |
| accepted | 确认 runId | 订阅/读取原 run；流失败不改回未受理 |
| definitive-failed | 原生受理结果明确未受理，或原 run 已有失败终态 | 用户显式新尝试；用新 ID 但保留逻辑操作关系 |

完整意图包括 workspace 身份、源/执行项目、conversation、消息 ID、clientRequestId、文本、附件、snapshotId、模型选择和 operationId；**不存 byokProvider 密钥**。恢复使用当前有效授权重新注入运行凭据，不因缺凭据自动换账号。

desktop 存储 facade 的 `get/put/delete` 为异步；put/delete 接受 expectedRecordId，冲突时返回冲突而非覆盖。仅 app renderer 可调用，键限定 Composer/send/revision/continuation 前缀；payload 服从既有容量限制。准备阶段写失败不 POST，未知请求不被容量清理淘汰。解析旧记录失败显示不可恢复原因，不当作空白自动开始。

## 6.5 创建 helper 项目的检查点

Revision/Continuation 的 CreateJournal：operationId、owner project/entry/version、targetProjectId、selectionFingerprint、checkpoint、可选 conversationId、可选关联 sendIntentId。`prepared` 阶段不要求 runId。

通过原 createProject 的显式 id 做恢复：不存在才创建；存在且 metadata.mokinaOperationId 匹配则继续；存在但不匹配返回 409。写快照和 Composer draft 分步完成可复验，draft-ready 前禁用发送。这个逻辑只为两个 helper 入口服务，不抽象成全局 Saga/Workflow/Operation 中心。

## 6.6 新增错误码与边界

| code | HTTP/发生阶段 | 可执行的下一动作 |
|---|---|---|
| MOKINA_SOURCE_CHANGED | 409 / 冻结前 | 重新读取选择；不发送当前请求 |
| MOKINA_CONTEXT_LIMIT | 413 / 冻结前 | 缩小选择；不自动截断 |
| MOKINA_SNAPSHOT_CONFLICT | 409 / snapshotId 已占用 | 核对原准备记录，不覆盖 |
| MOKINA_SNAPSHOT_UNAVAILABLE | 404/409 / 读取或校验 | 显示缺失/损坏；不从最新资料冒充重建 |
| MOKINA_OPERATION_CONFLICT | 409 / helper 创建恢复 | 打开已有操作或停止，不覆盖其他项目 |
| MOKINA_CONTEXT_NOT_SUPPORTED | 422 / 当前选择无法读取 | 更换资料或明确不纳入 |

上述确定的准备失败可以阻止 run POST。**不要把任何通用结构化 5xx 都解释成 definitive=false/未受理**；是否已受理由原生 admission 协议决定。身份、权限、模型、网络错误继续采用现有 taxonomy。

## 6.7 存储写入与兼容

快照和 blob 在受保护元数据存储原子落盘（临时文件、校验、rename），journal 先于副作用保存。所有新属性可选或独立 schemaVersion；不批量回填老项目，不将 version GET 变成迁移工具。Mokina off 构建不注入快照、不调用新增界面读取；旧客户端无新字段不受影响。

恢复包数据格式是第 07 文档的传输格式，不新增长期运行资源。路由集保持有界，不设计“通用上下文平台”和“通用恢复平台”。
