# 07｜指定版本交付与项目恢复

## 7.1 精确版本导出

所有当前/历史/候选可读版本，均从同一版本面板调用原生 HTML/PDF/ZIP exporter。修复面板内 HTML 按钮只允许 current 的条件，但继续保留只读权限限制。[S12]

点击导出时捕获 `{projectId, entry, versionId, contentDigest, format}`，此操作不可随界面后来选中新版而变化。内容优先取该版本 frozenContent；不存在独立冻结资源时必须警告，不能悄悄引用当前 assets 后声称历史还原。场景新生成自包含 HTML 继续遵守已有 report-contract。[S07/S09]

文件名建议 `成果名-vN-当前稿|历史稿|候选稿.ext`；manifest 保留原 versionId 与摘要，文件名只用于阅读。用户取消文件选择器是 canceled，不显示保存成功。导出期间文件或版本被移除时失败必须明确，不退回另一版本。

### 格式验收

HTML 在应用外部打开，主体、图片、样式和交互在已声明依赖范围内可用；不得需要 daemon 的短效 bearer URL。PDF 检查实际页数、中文、正文完整性、图片、页脚/表格和打印样式，不以“有文件”代替可读。ZIP 解压后从指定入口打开，内部引用不得指向开发目录或用户绝对路径。

桌面必须经过真实 native exporter；浏览器 fallback 可以保留和回归，但不能替代桌面验收。手工修改继续沿原文件写入/版本路径，不能为了导出另存一套 current 指针。

## 7.2 项目恢复包：明确缩小范围

本版新增的是**项目成果恢复**，不是整机备份或 SQLite 克隆。复用原生 export manifest/文件打包能力，增加受控的恢复清单。目标是项目资料、成果和版本能回到一个新的 Mokina 项目。

必须包含：原项目显示名、所有选定项目原件、当前/历史/候选版本及其冻结内容、版本 current/parent/base 关系、上下文快照、接续固定来源文件、每项文件大小与 SHA-256。项目名称、versionId 与相对路径均作为数据读取，不能当命令或写入绝对路径。

不包含：Codex/其他 Agent 登录信息、API key、OAuth token、MCP secret、插件可执行配置、原生 app-config、原始 SQLite、缓存、用户绝对路径、运行中的进程或可自动重放的 sendIntent。聊天/运行记录在本版只可选导出为只读文本，不承诺恢复成可执行会话。未发送草稿的日常重启恢复由 R05 负责，不依赖恢复包。

## 7.3 接口与清单（新增、复用原打包器）

`POST /api/projects/:id/mokina/recovery-export`：请求 `{operationId}`；复用当前项目读权限和原导出限制，从一致的版本清单捕获输入，然后打包；响应使用既有下载文件/结果引用方式。operationId 重试指向同一已捕获清单，不在导出进行中切换版本。若文件捕获期间变化，失败并提示重试，不输出混合快照。

归档根部使用 `mokina-recovery.json`，schema=`mokina.project-recovery.v1`，字段见 `contracts/mokina-local.ts`。普通交付 ZIP 不带这个标记，导入时不能猜测它是可恢复项目。

`POST /api/mokina/recovery-imports`：复用现有上传暂存机制；JSON 请求 `{operationId, uploadId, targetProjectId, projectName}`，禁止服务端读取请求中任意绝对路径。先校验清单/文件摘要/路径/容量，再按指定目标创建新项目；成功返回 `{projectId, warnings}`。重试同 operationId 恢复同一目标，目标已存在但不属于此操作返回冲突。

只按显式文件白名单导入；拒绝绝对路径、`..`、symlink、冲突条目和不匹配摘要。归档压缩前后总量上限沿现有上传/导入常量设置，必须在 T14 实施记录中绑定实际值，不能使用无上限解压。不同 schema 的未来包返回不支持，不尝试 best-effort 执行。

## 7.4 恢复语义

恢复到**新项目**，不覆盖当前数据。projectId/versionId 重新分配，内部 parent/base/current 引用按 mapping 重建；manifest 原 ID 保留为只读来源信息。候选仍是候选，不在恢复时自动采用；每个 entry 最多一个 current。

上下文快照内容和摘录保留，原外部 sourceRef 可作为历史定位存在；不能为了让旧链接变绿去读取旧项目最新内容。sourceDigest 和快照校验采用恢复包原值，快照的新归属封装与原 fingerprint 分开记录，不能修改 projectId 后仍沿用旧 fingerprint。

为避免设计第二套版本库，T14 使用现有受保护版本存储接口做一次性导入；原生接口不足时新增仅供 import 的 batch helper，不新增常驻迁移服务。导入全部校验完成后才将项目设为可进入；失败保留有标记的暂存操作，可重试或用户确认清理，绝不能让半份项目冒充恢复成功。

## 7.5 本地升级

本版更新采用用户明确替换 Mokina.app；不从上游下载 payload。Mokina 的产品数据/profile 身份在本地预览版本间稳定。升级前建议导出关键项目恢复包；schema 迁移沿原宿主迁移机制，记录备份和兼容范围，不写自己的并行 migration manager。

不保证较旧应用可打开新版数据。回退需要对应版本与已确认可恢复的数据包；不得建议直接把老二进制指向升级过的数据库。卸载/删除应用不自动删除用户项目，清理数据是单独明确确认的动作。
