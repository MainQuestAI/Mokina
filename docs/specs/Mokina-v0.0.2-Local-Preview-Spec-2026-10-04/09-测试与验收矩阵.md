# 09｜测试与验收矩阵

## 9.1 发布门

| Gate | 条件 |
|---|---|
| G0 基线 | PR3 最终状态、实际 merged/reviewed SHA 与当前分支关系；冻结设计及旧失败可核对 |
| G1 本机可运行 | 独立产品身份、真实 Finder 启动、Codex 连接、数据/进程/草稿隔离与重开 |
| G2 输入可信 | 七类解析限制、快照、来源变更、预算、实际注入回执、权限 |
| G3 工作闭环 | 真实场景管线、修订受理恢复、候选采用、固定来源接续，无暗中重发 |
| G4 交付可用 | 指定当前/历史/候选版本的外部可读文件与安全项目恢复 |
| G5 产品完整 | 冻结八视图、隐私/安全、i18n、两 edition 独立构建、无新增相关失败 |
| G6 用户能用 | 最终安装包在目标 Mac 完成 A/B/C 与重开/交付；专业和用户结论单列 |

G0–G6 全部通过才宣布 `0.0.2-local.1` 交付。每片可独立合并，不据部分门通过声称最终完成。P1 的视觉/i18n 仍纳入 G5；不能静默挪出本轮。

## 9.2 测试层级和证据

单元测试覆盖纯解析、digest、选择预算、状态转换；集成测试用真实 daemon/项目存储验证受理、幂等、版本 CAS；生产浏览器测试使用真实生产构建，mock Agent 只替代模型执行；桌面测试必须使用真实安装包、main/sidecar 和 exporter。专业评估必须真实模型，不从合成期望文件直接生成用户成果。

每个结果记录 sourceSha、BUILD_ID/产品版本、edition、平台/架构、数据隔离身份、命令、runId/operationId/版本 ID、实际文件及摘要。现有客户资料不用作故障注入；使用 `fixtures/` 和隔离目录。真实登录信息不得进入证据。

模型速度不作为确定承诺。记录本地启动到界面、受理到可见运行、首次有效成果用时和失败原因，用于定位体验问题，不设置“5 分钟一定完成”的硬门。

## 9.3 专业评分

A、B 各按五项 0–2 分：输入/约束遵守、关键判断与取舍、来源与事实、行动可执行、交付可读。每项 0 不通过，总分至少 8/10；总分不能抵消编造来源、禁止渠道被使用或预算错误。人工评分附具体例子，不仅写“模型效果较好”。

C 必须通过独立数字核对；比例用明确分母，缺失不当零，ROAS 不叫利润率，候选原因不说已证明因果。数据期望由 `fixtures/expected-metrics.json` 提供，不能作为模型任务输入。A 的变体改变预算后，不要求固定答案，但须解释相应资源取舍。

## 9.5 历史失败和范围回归

PR3 描述的八项 Web 失败是一个**待复验基线**，不是永久免费白名单。[S01] T00 用精确 base 复现测试名、错误签名与环境；本轮改到相关业务则该旧失败须修复或作明确的发布裁决，不能继续标“无关”。

每片至少跑受影响模块测试、guard/typecheck、必要生产 UI；改 contracts 同时跑 daemon/web/CLI 消费者。最终做完整相关回归、全量与基线差异、独立 on/off 构建。没有 GitHub checks 就写没有，不用本地绿等同远端 CI 绿。最小 CI 复用仓库工具规则，不另造复杂自动化平台。

## 9.6 缺平台/账号时的输出

非 Mac 环境可以完成代码、静态/集成测试、构建准备和所有能跑的用例，但 G1/G6 的真实 Mac 用例保持 not_run。真实模型登录、配额或外网受限时，保留已完成工程证据，并说明缺少哪个账号/能力；禁止用 fake Agent 结果替换专业验收。用户签收只记录实际用户行为，不能由 Codex 代签。
