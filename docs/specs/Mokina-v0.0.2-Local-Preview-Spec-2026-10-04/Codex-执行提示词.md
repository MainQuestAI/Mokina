先完整读取本包 README、00、01、08、09、11，以及仓库根和相关目录 AGENTS。再按需要读取其余规格与 contracts/examples。产品根是 `open-design/`；不要去上游另建工作台，也不要混入 LilithV3 或 Deck Master 项目。

本包规划基线是 PR3 head `53da96ca9080afb5b5141490d6e95858a6e18e9a`。撰写时 PR3 仍为 Draft、未合并。先执行 T00，读取最新 PR/main、最终复审状态、工作树与构建身份；若有新提交，按本轮影响核对差异，不重复开发已完成能力，不 reset 用户目录。

按 S0→S1→S2→S3→S4→S5→S6 推进。先打通真正从 Finder 启动的生产桌面切片，再补上下文/制作；不要把桌面依赖和数据隔离问题都留在最后。允许在依赖明确时并行，但共享合同、FileViewer 和发送 helper 由一个 owner 收口。

本轮关键要求：

1. 独立产品 profile、数据/profile/进程隔离，关闭上游更新和未配置云入口的隐性请求。内部 @open-design 包名和底座仍可保留。日常使用不依赖源码、pnpm 或开发服务器。
2. Codex 为主验收通道，尊重既有 CLI 和认证；Finder 环境可用。缺配置给明确动作，不静默修改全局配置或安装工具。
3. 复用现有七类资料解析，增加选定内容的不可变上下文快照和本次注入回执，不建立 RAG/知识库。上传、已选择、已注入与“模型理解”分开。
4. 修订入口必须复用 PR3 的发送前持久身份和 unknown 只读核对；接续项目创建须稳定 targetProjectId、可恢复检查点。任何丢响应/重启都不能盲目重复收费执行。
5. 保留 current/candidate/历史版本真相和原生采用 CAS。活动页由固定选定策略+品牌+素材在新项目真实生成；创建接续只是草稿，不自动发送。
6. 当前/历史/候选的精确版本导出和项目恢复包实际可用；不把成功 run、HTML 文件或 mock 测试等同于专业/桌面通过。
7. 继续使用仓库冻结设计包，校验 21 项摘要后补 P01–P08，不另做一套视觉。i18n、键盘、1280×720 和系统效果降级不能省略。

每个切片先形成可失败的用例，再修改并记录。测试遵循仓库工具与 package-scoped 命令，不新建根 build/test/dev 别名，不批量修改无关模块。保留用户已有 AGENTS/资料改动和客户数据；所有故障注入用合成输入和隔离数据根。

优先复用现有函数；新增模块只承担本包明确职责。不得扩大为新 Agent Loop、Workflow/Saga 平台、全局幂等平台、用户管理、来源图谱、完整 BI 或自动 Meta Skill。允许在同一职责范围内调整建议文件名，并在 implementation-map 留证。

每次报告写清 base/head、已完成/未完成、实际改动、测试命令和结果、真实/模拟/历史证据、阻碍和下一切片。真实模型/Mac/登录条件不具备时，完成可独立推进部分，相关验收保留 not_run；不得用 mock 代替真实证据，也不得让环境阻碍变成无关代码扩张。
