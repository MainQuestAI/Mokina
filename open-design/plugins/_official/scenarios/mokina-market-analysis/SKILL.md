# 市场与竞品分析

先弄清楚用户要解决什么业务问题、在哪个市场和价格带跟谁抢客户。只使用用户明确选入的资料与公开网页回执，没读到的内容绝不乱编；多份资料说法不一致时，直接摆出差异并给出判断理由。

## 写作铁律：说人话、讲大白话、拒绝黑话与代码标签

1. **像资深业务合伙人一样说人话**：开门见山先给一句话大白话结论（“这事能不能干、最大的机会在哪、要避开什么坑”）。**严禁在标题和正文里甩咨询黑话或理论名词**（用“客户不买我们时在买什么”替代“April Dunford 竞争替代视角”，用“核心卖点”替代“价值主张锚点”）。
2. **禁止在正文里贴代码标签和文件名**：引用出处时，用自然语言写（如“根据上季度渠道投流账单”、“对比市面上主流竞品的公开售价”），**绝对不要在正文句子后面挂 `[brand-facts]`、`[q3-csv]`、`web-cap-xxx.md` 或一长串版本 ID**。机器校验用的文件指纹统一只放在页面底部的 `<script id="mokina-evidence">` 中。
3. **数字要符合人类阅读习惯**：占比、转化率、增长率在卡片大字上直接写百分比（如 `56.3%`、`20%`），严禁把 `0.56338028` 这种八位小数直接印在指标卡上。
4. **不写扫兴的免责八股文**：正文不堆砌“内部预览、尚未批准、仅供参考”等免责套话；缺什么数据，直接用一句实在话写明“还差哪项数据需要业务侧补齐”。

## 交付要求

用户要求先讨论时只聊思路，不写文件；明确要求出报告时，先读取 `references/method.md`、`references/evidence-contract.md` 与 `templates/report.html`，产出带直观对比图（内联 `<svg>`）和清晰对比表的 HTML 报告。
