# 可操作营销方案与 GTM 策略方法论 0.1.0

输入：明确的工作目标、目标受众、报价单/资料、预算总上限、周期、内部工时容量、禁投/禁做红线与现有渠道基线。围绕“如何用有限预算与工时打穿增长瓶颈”组织方案。

## 1. 目标、硬约束与禁投红线穿透（`#objectives`）
- **双约束并列**：将资金预算上限（`data-budget-limit`）与内部团队工时上限（`data-capacity-hours`）并列作为硬边界；外包采购单价不能抵消内部审稿、对接与复盘工时。
- **实质禁令穿透**：禁投/禁做红线按实质业务行为检查——例如明确“禁止线下活动”时，方案中不得出现换皮的“线下品鉴、快闪摊位、门店到访预约或现场接待”。

## 2. 漏斗瓶颈诊断与 Message House 价值主张屋（`#audience`）
- **漏斗卡点定位**：明确当前核心卡点位于“目标客群认知触达”、“专业信任破冰”、“低摩擦留资/首单转化”还是“老客复购激活”，拒绝把泛曝光点赞等同于商业转化。
- **Message House（价值主张屋）**：
  - **顶层核心主张（Core Value Proposition）**：一句话回答“为什么目标客户现在必须选我们而非替代方案”；
  - **三大支撑支柱（Pillars）**：痛点共鸣钩子 + 产品差异化利益点 + 可核验的事实背书（逐一绑定 source ID）。

## 3. 两个实质互斥的战略路径对比（`#directions`）
- **拒绝换皮对比**：提出至少两个在**目标人群切口、核心渠道机制、验证速度与风险结构**上实质不同的战略方向（例如：方向 A“依托高意向私域/垂直社群的深度种草与高客单转化” vs 方向 B“依托结构化对比内容与搜索截流的持续获客”）。
- **决策条件矩阵**：并列对比方向 A 与方向 B 的成立前提、资金与工时占用、试错周期及不可兼得部分，明确写出“满足何种业务条件时选 A、何种条件时选 B”。核心策略主张使用 `data-mokina-field`（`data-mokina-kind="strategy"`）标记，支持用户在界面中微调或跨版本组合章节。

## 4. 阶段推进排期与止损纪律（`#actions`）
- 按周次或阶段（如 W1 筹备与最小测试 → W2 信号复盘与主渠道放量 → W3-W4 收口与资产沉淀）拆解具体动作、交付物规格、内部负责人角色、前置依赖及触发暂停的止损条件。

## 5. 预算与内部容量双约束定点核算（`#budget`）
- **定点预算表契约**：使用 `table[data-mokina-budget]` 配合 `data-budget-limit` 与 `data-capacity-hours`；每行 `tr[data-budget-item]` 严格包含 `data-quantity`、`data-unit-price`、`data-amount`、`data-hours` 四个纯十进制数值单元格，并在行内注明对应报价来源 ID 及包含/不含范围。
- **留白与缓冲哲学**：少花钱、保留未分配机动预算是理性的商业取舍，绝不为了凑满预算上限而塞入无依据的投放项；不同战略方向各自独立建表核算（分别对应汇总序号 `0`、`1`），绝不将互斥方向混加在同一张总表中。

## 6. 北极星指标口径与 MVP 止损线（`#measurement`）
- **可复算口径**：每个核心 KPI 明确定义分子、分母、统计时间窗与数据来源；涉及比例验证时使用 `data-mokina-ratio`（零分母明确显示“不可计算”）；缺少历史转化率或毛利数据时，聚焦前端可观测的先行指标（如有效咨询成本、高意向留资率），不虚构确定性 ROI。

## 7. 证据台账与待确认前提（`#sources`）
- 集中列出每个章节引用的资料/网页回执、定位、逐字摘录与读取限制，保持主方案版面的整洁与权威感。
