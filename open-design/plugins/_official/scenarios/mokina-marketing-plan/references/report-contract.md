# Mokina 营销成果 HTML 约定

- 单个自包含 HTML 文件，内联 CSS、脚本、图表数据和 SVG。不要引用项目内会漂移的图片、CSS、JS；无法内联时明确说明，不能声称历史版本可独立交付。
- 每个可修改的顶层章节同时使用稳定且唯一的 `id` 与同值 `data-mokina-id`，如 `objectives`、`audience`、`directions`、`actions`、`budget`、`measurement`、`sources`。这些章节之间不得嵌套；内部锚点只用普通 `id`。ID 不随标题措辞改变。
- 引用在对应判断附近标出来源 ID；来源表记录文件或网页、定位、访问时间、实际摘录，以及“原文”“摘要”“推断”的区分。
- 数值写明单位和时间口径；缺失、空值、公式无缓存值和估算不得混为零或事实。
- `@media print` 保持正文、表格、来源可读，避免关键表格行被截断。图表同时给出文本或数据表。


## M3 受控成果操作（首批）

- 策略条目使用纯文本叶子元素，例如 `<p data-mokina-field="positioning" data-mokina-kind="strategy" data-mokina-label="定位主张">…</p>`；研究矩阵单元格用同一字段标记及 `data-mokina-kind="matrix"`。字段 ID 全文唯一，稳定不随措辞改变；不得把脚本、样式或富文本节点标成可编辑文字。
- 预算沿 evidence-contract 的数量、单价、金额和工时标记。需要同步显示的总金额、余额和工时分别用 `data-mokina-budget-total="0"`、`data-mokina-budget-remaining="0"`、`data-mokina-budget-hours="0"` 的纯文本元素；值是预算表在全文中的零起始序号。不要在未标记正文中重复预算数字，避免用户改表后文字过期。
- 操作只保存候选；合并方向仅替换明确选定的同名章节，原方向不变。用户需通过版本比较审阅业务变化再采用。带图片/脚本等复杂内容继续使用章节修订，首批受控编辑不承诺任意 HTML。
- 研究→策略→活动页使用固定版本/片段，补充背景由用户明确选入。下游保留品牌事实、优惠条件、KPI定义、时间和CTA；缺失信息标记待确认，不替用户编造。上游新版本不自动改变旧下游。
