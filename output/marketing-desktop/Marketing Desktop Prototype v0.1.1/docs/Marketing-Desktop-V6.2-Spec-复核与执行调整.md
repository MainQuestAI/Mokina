# Marketing Desktop：V6.2 基线复核与执行调整

日期：2026-09-13。性质：源码复核、定向状态探测与实施方案修订；本轮没有修改应用代码或接入 Runtime。

## 1. 结论

v0.1 的方向继续采用：可选项目、目标驱动计划、可调整的工作依据、通用成果、真实 Agent 执行，以及品牌战略／社媒内容／运营分析三类验收。V6.2 的改动主要增加了输入、决定和交接的完整性，并未使底层计划和生成脱离产品上市链。

执行方案需要三项实质调整：

1. **起点从“已接通 Codex 的桌面工程”改为“V6.2 离线原型＋待接入的执行底座”。** 当前 Mokina 没有 Runtime，也没有桌面宿主工程证据。必须先建立最小真实请求闭环，再扩大 UI 改造。
2. **复用 V6.2 已经补齐的输入快照、候选决定和接续能力。** 去掉重复建设事项，改造它们的项目／SKU／渠道适用范围，以及工作归属。
3. **从项目唯一交付计划转为会话承载的工作目标。** 原有上市计划保留为可选专业方案；独立检索、人工内容接续和一般对话接到同一工作边界，避免发展出两套互不相通的工作系统。

新执行依据：[修订版 Spec v0.2](./Marketing-Desktop-Agent-Spec-v0.2-V6.2基线.md)。原文保存在 [v0.1 存档](<./reference/Marketing Desktop Agent v6 Spec v0.1.md>)，其中的执行指令作为待评审材料处理，未据此直接开展代码实施。

下一阶段优先只读检查这些候选组件及调用依赖，复用最小可运行部分。不能把该工程的旧前端直接当成 V6.2，也不能把 Codex 桌面当前安装的 skills 自动当成应用子进程可用的能力。

## 6. 对完成状态的纠正

本轮已完成 Spec 复核与修订，应用仍为原 V6.2。新 Spec 的实施完成条件是：同一实际 Agent 路径承接三类任务，用户能追问、改稿、检查依据和选择性复用，且原专业场景回归通过。

本轮没有把源仓历史 74／66 项结果写成当前回归通过，没有将相邻 Runtime 的代码存在写成已集成。浏览器历史阻断也不作为永久事实；实施时需通过平台允许的入口重新核验，遇到明确策略拒绝时处理访问条件。
