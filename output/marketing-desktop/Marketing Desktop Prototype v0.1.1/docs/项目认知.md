# SpaceMaster V6.2 项目认知

## 一句话定位

一个以 Lilith 工作台为壳、面向 SpaceMaster 上市内容生产的独立浏览器原型，重点展示“资料有依据、成果可追溯、决定由人收口”的工作方式。

## 入口与依赖

主入口是仓库根目录的 `Lilith SpaceMaster Demo V6.html`。页面是已内嵌 CSS/JavaScript 的单文件，但素材原图通过 `public/demo-spacemaster-v6/payloads/*.js` 按需加载，因此入口和 `public/demo-spacemaster-v6/` 需要一起保留。

维护源集中在 `src/demo-spacemaster-v6/`。`base/` 是基础工作台；其余模块按输入、成果、决策、工作分支、素材生产和验证拆分。`build.mjs` 负责从源合成单文件，`package-v62.mjs` 负责生成离线包。

## 核心对象

| 对象 | 作用 | 关键边界 |
|---|---|---|
| Project | 持久化项目上下文空间 | 上传不代表事实确认 |
| Task | 面向交付物的工作项 | 不等于 Agent 内部步骤 |
| Source / Snapshot | 资料、证据摘录和固定输入 | 旧版本保留，失效资料不能继续当有效输入 |
| Artifact / Version | Strategy、FABE、Message House 等成果 | 草稿、候选、采用、批准分开保存 |
| Decision | 采用、反选、审批与理由 | 模型或连续流程不能代替用户决定 |
| Handoff | 外部系统或正式使用的交接记录 | 本地记录不证明外部成功 |

## 当前主要场景

默认演示围绕 SpaceMaster，覆盖项目创建、资料输入、产品策略、FABE、Message House、图片/海报素材、官网与门店渠道范围、候选修订、交付集合和人工交接。V6.2 同时保留德国官网海报的独立演示分支，以及原有墨西哥上市场景的兼容保护。

## 已知未决项

产品/PIM 唯一性、国家/语言/渠道清单、客户审批对象与回传、Content Library 字段和真实回执、素材真实性/授权/声明、真实浏览器长流程与离线打开，均需独立确认，不能由本地页面中的“确认”按钮替代。
