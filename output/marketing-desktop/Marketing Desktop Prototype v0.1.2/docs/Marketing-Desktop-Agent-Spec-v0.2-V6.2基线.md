# Marketing Desktop Agent 迭代 Spec v0.2

日期：2026-09-13。产品交互基线：SpaceMaster V6.2（发布号 6.2.0）。文档版本 v0.2 不修改应用版本号。

本文件将 v0.1 从 V5 附件基线调整到当前 Mokina 的 V6.2 实现；它是下一轮实施依据，本轮仅完成文档修订与源码复核。原文件保存在 [v0.1](<./reference/Marketing Desktop Agent v6 Spec v0.1.md>)；当前事实和代码锚点见 [复核与执行调整](./Marketing-Desktop-V6.2-Spec-复核与执行调整.md)。发生冲突时，当前用户指令优先，其次采用本文件的 V6.2 修订内容。

## 1. 目标与实际起点

目标是让营销人员在同一工作台直接表达目标、提供资料、讨论取舍、取得成果和继续修订。品牌战略、社媒内容与运营分析共用一套工作机制；产品上市是一种可选专业方案。

当前可复用的是 V6.2 的对话／成果工作面、项目组织、证据摘录与输入快照、候选版本、人工采用、固定提交、素材集合和接续交接交互。当前 Mokina 没有已接通的 Codex 执行底座，也没有桌面宿主或可独立重建的完整开发环境。HTML 是离线原型；不能以当前 Codex App 中打开了该目录，推断产品已有桌面能力。

本轮实施先以 V6.2 工作面和核验后的本地执行服务形成可运行产品路径。桌面安装包、自动更新、托盘、全盘索引等不纳入本轮必要条件。若后续明确选定已有桌面宿主，可复用其文件和权限边界；本 Spec 不要求新增 Electron／Tauri 选型。

### 1.1 本轮必须产生的提升

| 提升 | 对营销人员的实际效果 |
|---|---|
| 无项目工作可真正执行 | 不用先填 SKU 或创建上市项目，就能分析数据、讨论品牌和写内容 |
| 计划取决于当前目标 | 只需要社媒文字时可直接产出，不自动扩展为完整上市交付 |
| 本次依据可检查和调整 | 能知道提交了什么、实际读取了什么，换资料后下一次执行相应变化 |
| 通用成果可编辑、可引用 | 普通文档、排期表和未知文件都可保存，多份同类方案不会相互覆盖 |
| 使用真实 Agent 能力 | 输入变化影响结果；失败、取消和恢复与实际运行一致 |
| 分析能接续后续工作 | 用户选择一个结论后，带着指定版本与必要依据开始下一件事 |

### 1.2 本轮不扩展的范围

不新增多 harness 切换、通用工作流引擎、完整营销本体、Skill 市场或自动进化系统；不要求接通广告投放、CRM、社媒发布、完整 DAM 或企业审批中心。沿用 V6.2 视觉语言，不以通用化为由先进行大规模界面重做。

Meta Skill 保留能力元数据与显式反馈接点。本轮不自动安装社区代码、不自动改写共享技能、不把业务资料自动沉淀为跨项目长期偏好。

## 2. 先建立可实施基线（W0）

1. 恢复匹配 V6.2 源文件哈希的 6 个测试与实际测试依赖；当前副本只有历史 TAP 和 checks，不具备完整测试树。
2. 补齐 `build.mjs` 实际使用的共享产品图、图标、品牌素材、字体和 Pretext 依赖，记录来源与本地路径。对外分发时另核第三方资产许可；本轮本地开发不需要扩大为资产替换项目。
3. 将本轮使用的构建／测试／打包路径定位于 Mokina，修正文档路径。原始 V6.2 HTML／ZIP 作为基线保留，新产物独立定位。不得运行会写回源仓的旧脚本。
4. 建立独立副本的验证入口。旧 V5 树缺失时不伪报其保护检查通过；保留原始 hashes，分别说明本地可测范围与源仓历史范围。
5. 明确当前存储键、备份 schema、示例注入位置、新旧数据权威来源及迁移出口。尚无 Git 时不以本 Spec 为授权初始化 Git、推送或部署。

退出条件：本地有可复现的构建、启动和验证命令，V6.2 基线可加载，核心业务测试有本地结果；差异与既有缺陷有记录。通用化后确需改变的旧测试按业务范围修订，不能单纯删断言来保持通过数量。

## 3. 工作身份与对象契约（W1）

### 3.1 会话承载一件持续协作的工作

优先使用现有应用 `thread.id` 作为逻辑工作身份，增加目标、范围、资料与成果关联的最小元数据。不同时引入相互竞争的 Work、Session、Task 生命周期。

一个新会话承载一个主要目标，可产生多个成果，允许解释、追问、缩小范围、局部修改。简单问答可只返回回答。出现另一个营销词汇不自动拆分；用户明确开启无关工作时创建新的会话边界。

应用会话与 Runtime 会话分开记录。候选 Runtime 可能按 conversation＋lane 建立执行会话，严格来源排除也可能创建新的干净会话；不能强行假设两者永远一对一。用户看到的工作身份保持稳定。

### 3.2 最小关联

下表是语义要求，具体字段名可沿用现有存储。

| 对象 | 最小关联／字段 | 处理要求 |
|---|---|---|
| 应用会话／工作 | 稳定 ID、目标／范围版本、可空 projectId、资料与显式成果引用 | 当前工作依据按会话收集 |
| 计划 | 所属工作、计划版本、目标、拟采取动作、输入引用、预期输出、范围排除项 | 不按项目只取最后一个草稿；同类输出允许多项 |
| Run | 应用工作 ID、Runtime 会话／运行 ID、Context 快照 ID、目标引用、幂等标识、状态 | 创建时绑定，后续不跟随 UI 当前选择 |
| 成果 | ID、所属工作、可空项目、类型／格式、版本、生成来源 | 新成果明确保存会话归属；类型不代表唯一性 |
| 局部修订 | 成果 ID＋基础版本＋稳定条目或段落 ID | 第三条不能只按排序索引或最新 kind 猜测 |
| Task | 用户明确的交付或待处理事项、工作／计划关联 | 不为每个模型步骤创建一条任务 |
| 独立工作 job | 固定所属工作、父任务／来源引用、现有类型状态 | 复用 `workflow-branches` 记录，不再形成独立的顶层工作身份 |

### 3.3 Project 可选，并支持一般营销组织

创建项目的最小输入是名称及可选目标。品牌、活动、运营分析项目不强制产品、SKU、市场、语言或渠道齐备；选择“产品上市”方案时才显示相应专业字段和必要条件。已有产品项目保留原数据。

关联项目用于组织和提供候选资料，不能自动将项目所有内容提交给 Agent。无项目工作使用明确的个人工作区／应用授权目录；仅在实际写文件没有可用目录时请求选择位置。

“当前工作”只显示本会话的成果、运行和显式引用；项目页允许汇总并清楚标出范围；全局成果库可查找全部，但可见不等于自动使用。

### 3.4 保留旧状态的最小迁移

V6.2 的 `newArtifact` 虽接受 tid，却未写入成果对象；不能直接声称旧成果均有可靠会话归属。优先利用已保存的消息成果引用、Run 返回记录等明确证据建立关联；多个会话引用或归属无法唯一确认时，保留为项目共享／历史成果，供显式引用。不得按类型、当前页面或最近会话猜测归属。

独立 jobs 创建时绑定工作，保存时使用该绑定；旧 jobs 不因当前导航而重新归属。新成果与旧 ID、版本、采用、提交快照保持兼容。迁移重复执行不重复创建对象；保留备份与可验证恢复方法。存储 schema 与发布号分开演进，确定唯一业务数据权威，避免浏览器状态与后端双写分叉。

## 4. 先打通真实最小闭环（W1）

### 4.1 候选复用入口

相邻 `Lilith-原型-dev` 的 `runtime/server.mjs`、`run-manager.mjs`、`store.mjs`、`mcp-bridge.mjs` 和 `src/probe/app-server.mjs` 是已定位的候选。实施时先核验其依赖、数据模型、授权设置、协议和最小测试，再将必要组件适配至 Mokina。避免整仓合并旧前端与历史状态。

本文件不指定当前 Codex 协议版本或 API 参数。以实际本地实现、CLI schema 和成功调用记录为依据；工具清单和鉴权以应用运行进程为准，不继承对 Codex 桌面自身能力的假设。

### 4.2 第一条纵向路径

无项目新工作 → 提交一段用户资料和目标 → 固定请求快照 → 实际 Codex 执行 → 返回回答／普通文档 → 成果保存 → 用户追问或修改指定版本。

这一阶段即提供最小文档工作面和实际输入清单，不等待全部通用编辑器完成。失败要显示实际错误和可重试范围；未保存的文字响应不能显示为已生成文件。

真实执行入口在最高层输入适配处分流，避免继续落入 `project-input.js` 的固定回复、`makeContent` 模板或 demo 故事。演示入口与运行记录明确标注 executionMode；真实失败不回落为模拟成功。

### 4.3 执行与文件约束

事件按 Run 和工作 ID 回写。重复消息、断连重放和迟到结果不重复创建成果；取消后的结果不得将状态改回成功。修改时基础版本已变更，保留为待比较候选或报告冲突，不覆盖新内容。

沿用核验后的真实取消、状态查询和恢复能力。仅支持重新执行时显示“重新执行”；仅停止动画不称为暂停。单任务运行可以继续保留，无须为验收额外建设并发平台。

文件通过实际授权和文件标识进入请求。读取、保存、预览、下载必须关联实际文件及版本；HTML 结果用隔离预览，未知文件仅提供可靠信息和打开／导出入口。凭据不进入 HTML、浏览器备份和成果导出。

退出条件：至少一件非上市工作实际完成输入、运行、保存、追问和修订；切到另一工作时旧结果仍归原工作；失败与取消有准确状态。未完成这一条，不把 UI 占位页面标为通用 Agent 已接入。

## 5. 目标驱动计划与动作输入（W2）

### 5.1 统一入口与协作模式

沿用 V6.2 对话、成果 Canvas、标签页和侧面板。首页示例改为品牌战略、社媒内容、运营分析，示例只填入目标或经显式选择导入合成资料。SpaceMaster 通过“产品上市示例”继续进入；新真实工作不自动装入样例上下文。

| 模式 | 行为 |
|---|---|
| 协作 | 简单工作直接响应；多步工作给出相关方案，再按用户范围继续 |
| 先定计划 | 形成目标、输入缺口、动作和预期成果；确认前不开始制作或外部动作 |
| 自主完成 | 在明确目标和范围内连续执行，可为具体缺失输入或权限停下；不自动批准或发布 |

解释、追问、停止、排除动作和“只分析”在各模式下均按其真实意图处理。用户刚选择“先定计划”只约束制作节奏，不把随后的解释问题转换成新计划。不为每个输入新建 Task。

### 5.2 将上市方案限定为专业预设

`BATCH_DEPS`、`BATCH_ORDER`、`projectPlanRules` 和德国图像链只在用户选用对应方案时生效。系统可推荐预设，用户可以调整目标和范围；明确业务要求保留来源及适用范围。

一般营销计划由现有 Agent loop 根据目标与实际输入形成。应用负责呈现确认后的方案和固定引用，不在前端重建“品牌词→品牌流程、社媒词→社媒流程”的关键词规划器。

现有消息、计划与批次 UI 可以复用；计划项从固定 kind 清单扩展为稳定动作／交付项引用，允许两个同类型输出。展示计划可与工具记录关联，但没有底座事件时不能把计划项直接标为已执行。

### 5.3 按动作判断必要输入

| 规则 | 例子 | 本轮处理 |
|---|---|---|
| 方法建议 | 写文案可参考 MH | 可忽略；已有表达可直接作为来源 |
| 必要输入 | 算互动率需要曝光、互动和口径 | 缺失只影响对应计算；可继续其他描述分析 |
| 产品事实条件 | 对某型号写容量声明 | 检查该声明适用的型号与证据；不强迫其他品牌任务填产品表 |
| 适用业务要求 | 已选上市交付范围、已确认品牌约束 | 显示来源、作用对象和原因；演示规则不成为全局制度 |
| 正式动作条件 | 发布、发送、覆盖正式文件 | 使用实际权限机制与明确用户意图 |

保留 `V62Inputs` 的核对、快照、来源失效与历史保护。`inputsReady` 继续可描述产品输入状态，但不再决定全部营销动作能否执行。不要求每份普通附件都先完成人工摘录确认才可读取；未核对资料可以供分析，不能自行升级为已确认产品事实。

建议由当前目标与缺口产生，可忽略、可编辑；完成时允许结束。用户排除后续生产／发布后，不创建相关待办。

## 6. 本次工作依据（W3）

在现有检查面板中增加“本次依据／执行状态”，项目背景作为来源入口。默认给营销人员呈现资料、缺口和选择，技术明细可展开。

| 来源状态 | 界面含义 | 证据来源 |
|---|---|---|
| 可供参考 | 在本次授权范围内可选 | 当前工作附件、显式项目关联或用户检索结果 |
| 已提交 | 内容或引用已进入本轮请求，区分只提交路径与提交正文 | 应用生成的实际请求清单 |
| 已读取 | 工具实际打开了资料 | 工具记录、文件／版本定位；底座没有记录时不推断 |
| 成果引用 | 指定段落或结果引用该版本 | 成果引用关系及定位 |
| 已排除 | 后续请求不主动提交该项 | 上下文组装结果；不能据此声称清除了历史会话记忆 |

每次 Run 快照至少包含工作、目标／范围版本、选中资料、成果 ID／版本、内容哈希或固定内容、排除项、提交摘要和时间。复用现有产品快照作为一种输入，不把它改成唯一通用格式。

仅在当前授权候选范围内展示未选用项与排除原因，不扫描全部工作区来凑清单。优先使用用户本轮指定资料和必要历史，项目背景与偏好需适用；冲突来源显式展示。

运行开始后输入固定，面板调整默认影响下一轮。底座已读资料若需严格排除，创建干净执行会话并重新提交允许历史；无法保证时准确说明限制。历史引用保留原版本，来源撤权／失效按使用范围重新检查。

缺口用可执行动作表达，例如“缺曝光数，暂不能算互动率，可以先整理互动量趋势”。普通草稿不因缺客户正式审批合同而全部停住。

## 7. 成果、复用与能力（W3／W4）

### 7.1 通用结果和局部修改

| 成果形式 | 本轮最小能力 |
|---|---|
| 文档／Markdown | 查看、编辑、保存候选、版本比较、来源引用、导出 |
| 表格／CSV | 列与行预览、字段与口径说明、导出；内容排期支持编辑；原始分析数据只读，变更生成派生版本 |
| 图片／HTML | 使用实际支持的安全预览与文件打开方式，不要求新增生图引擎 |
| 未知类型／文件 | 保存元数据、来源与文件引用，安全兜底；不因 `KIND[kind]` 缺失崩溃，不伪装可编辑 |

兼容层须覆盖创建、结果卡、详情、版本、引用、任务显示、导出和恢复。只给内容渲染加 default 分支不足以通过未知类型验收。

“另做一份方案”创建独立成果；“修改此方案”绑定 ID／基础版本。“缩短第三条”绑定稳定条目 ID，保存新候选，其他四条保持内容不变。用户采用记录与生成记录分别保留。普通回答无需强制采用，普通草稿完成不依赖企业审批；有正式用途时再显示适用审批与交接。

V6.2 的成员选择／反选、集合候选、不采用／暂缓／重新考虑、固定提交和撤回继续保留在相关专业成果中，不扩展成所有普通文档必经的审批表单。

### 7.2 统一已有独立工作与接续

复用本地检索、描述治理、文字检查、内容接续和交接记录。它们作为同一工作中的能力入口或关联事项，保留各自状态；不要求再选择一套独立工作空间。

`continueFrom` 扩展为引用任意可用成果版本或指定片段。由用户选择哪些结论带入新工作，不把整个上游项目自动复制过去。普通备忘录和数据分析无需市场／语言／渠道齐套；相关本地化任务才补充这些条件。事实变化需要核对受影响输入，但不一律强制重建 FABE/MH。

新工作不继承旧成果在其他市场、语言、用途中的批准。新 job 创建时绑定工作与来源，后续保存不受切换导航影响。

### 7.3 能力可用性与 Meta Skill 接点

沿用能力入口，记录名称、用途、来源／版本、输入、结果形式、权限／依赖、当前可用状态和最近验证依据。区分“已可用／需要配置或授权／仅演示／暂不支持”，以实际运行环境为准。

三类任务不要求分别安装三个新 Skill，基础 Agent 能完成时直接使用。外部读取按工具授权范围执行；演示源链接只代表来源登记，不代表已抓取核验。

最小反馈包含当次目标、实际使用能力及版本、引用、用户采用／修改／放弃、可选理由与完成情况，复用现有活动记录。没有点击不推断为负反馈，一次修改不自动改变共享 Skill，跨工作偏好保存需要用户明确表达。

## 8. 验收故事（W5）

全部真实故事沿同一输入、执行、Context 与成果路径。合成资料显式标记；每个故事至少一次换表达和一次改变输入，并用一个未预设任务检查通用性。确定性测试、真实执行、浏览器操作和人工质量评审分别记载。

### S1：品牌战略

新个人工作，无项目。提供“北岚生活”虚构家居服务品牌的两份合成访谈摘要，分别说明年轻租住人群和有孩子家庭的需求与顾虑。用户请求：90 天品牌认知、比较两类受众、只能维护两个内容触点，提出有取舍的方向与验证计划；不制作产品文案、不创建上市项目。

验收：形成有依据的备忘录，解释取舍、两个触点和验证方法；不凭空补市场份额。无 SKU、FABE/MH 和图片门槛。追问“为何不同时覆盖”只解释；“保留方向，再补一个对照方案”产生第二份独立成果。输入访谈变化后理由相应变化。

### S2：社媒内容

新工作，项目可选。提供带来源的产品事实、已确认表达和旧文案。请求下周五条社媒文字与排期表，含目标、角度、正文和建议行动，不要图片，不重做 Strategy/FABE/MH。

验收：一个含稳定条目 ID 的结构化成果或五份关联文案均可；第三条能准确选择和缩短，其他四条保持不变，旧版可查看。用户明确不需要发布后不创建发布任务。已有事实直接进入请求，不要求在新项目重做上游成果。

### S3：运营分析与新工作复用

新个人工作。用户请求比较两期社媒数据，区分结构变化与分组表现，给出两项实验建议；先不写文案、不改排期。以下为合成数据：

previous,practical_tips,30000,1800
previous,product_intro,10000,300

测试约定互动率＝互动次数÷曝光次数。

| 指标 | 前期 | 本期 |
|---|---:|---:|
| 总曝光 | 40,000 | 40,000 |
| 总互动 | 2,100 | 1,550 |
| 总体互动率 | 5.25% | 3.875% |

| 实用内容曝光占比 | 75% | 25% |

总体下降 1.375 个百分点，不代表两类内容都变差。先用前期分组率与本期权重计算为 3.75%，结构项 -1.50 个百分点，分组率变化项 +0.125 个百分点。这是特定顺序的描述性分解，不是因果证明；不能推断销量或广告收益。

成果应含可核对表格、计算口径、主要发现、两项建议实验及数据不足。计算过程须可复核。随后用户选择“采用增加实用内容的方向，另开工作做下周三条内容计划”，新工作显式引用该分析版本及必要摘要，不自动继承全部历史，不声称实验已奏效。

### R1／R2：V6.2 专业回归
