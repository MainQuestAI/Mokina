## 整合追加修复

- 计划有错误时禁用开始，并直接提供补资料入口；保存草稿继续可用。
- 新产品结构化工作稿仅消费自己的固定事实，生成/修改/导出不进入旧墨西哥产品参数或产品图路径。
- 旧首页检索/检查入口与独立工作使用同一路径；空状态可补输入。
- 独立工作、修复及存量编辑草稿按工作上下文保留；返回保持原位置与对话草稿。
- 待处理保留采用/审批两主类，补输入、接手、异常、交接与正式使用待确认放在其他人工事项中。
- 内部创意评审通过仍显示“待正式使用确认”，不会让等待业务决定的任务看起来仍在自动生成。
- 自动故事显式选用成员，明确内部评审用途；故事章节完成与业务完成分别记录，不自动生成 CL 成功记录。

## 已保留的边界

1. 普通读取/制作/检查/保存连续运行；只有具体事实、业务取舍、作用范围和正式操作才需要用户决定。
2. 采用与审批、成员与集合、语言与国家、文件与成果版本分别保存。
3. 内容快照固定；使用资格动态核对。普通资料更新不覆盖旧版，明确失效不能继续当有效输入。
4. 原图、旧成果、提交、接手和历史接收记录不删除；迁移幂等，不要求清浏览器。
5. 无真实外部服务时只提供可检查的本地草稿或交接记录，不把模板文字、读取延时或人工回执当作真实接口执行。

## 验证方法与结果入口

当前通过 **74 项 Node 状态/组合测试和 66 项构建、资源与兼容检查**。完整故事覆盖21个章节、7项交付批次、13条不重复用户消息和2次德语内部评审提交；没有生成虚假的外部接收记录，结束后回到德国项目任务页。这些结果不等同于浏览器交互通过。

```bash
node src/demo-spacemaster-v6/build.mjs
node src/demo-spacemaster-v6/verify-v62.mjs
node src/demo-spacemaster-v6/package-v62.mjs
```

- `qa-v62/domain-tests.tap`：实际 Node 测试输出；包括真实业务函数在 VM 中的运行，UI/等待/图片解码使用替身。
- `qa-v62/checks.json`：状态测试数量、构建脚本解析、当前 HTML 哈希、源文件哈希、20 张原图哈希及 V5 基线保护检查。
- `qa-v62/release-manifest.json`：包内 HTML、20 张原图与本轮验证边界。
- 打包目录旁的 `qa-v62/package-checks.json`：ZIP 完整性与归档哈希；该记录在归档完成后生成，不自引用到包内。
- 新增文件有明确版本号；打包前验证当前源码哈希，拒绝把旧检查结果用于新源码。
- Impeccable 检测用于新增 UI 源码的静态检查，不是布局/可访问性认证。

**本轮未做浏览器点击、截图、视觉、真实下载或离线打开实测。** 浏览器 URL 策略阻止该原型访问，本轮未通过替代浏览器、HTTP 或 CDP 绕过。旧的截图、七任务“正式完成/CL接收成功”测试结果不放入6.2验证包，不沿用作本轮通过证据。

完整自动故事的组合测试只验证业务状态和消息，不证明输入动画、滚动、焦点或像素显示。企业接口、客户规则、真实文件生成及正式发布必须单独验收。

## 仍需外部确认/验证

- 产品编码/PIM接口、项目与市场渠道的业务唯一性。
- 正式审批对象组合、审核人/代理范围、审批系统与状态回传。
- CL允许字段白名单、目录/对象映射、文件原生上传审批、真实回执。
- 首期国家/语言/渠道清单、真实性/授权/声明证据、模板/实际生成能力。
- 真实浏览器的当前页面与长流程、桌面尺寸、键盘/焦点/下载/离线打开。

以上不是通过点击“确认”即可解除的程序条件；本版保留可见限制与交接事项，不宣称已经替客户作出决定。
